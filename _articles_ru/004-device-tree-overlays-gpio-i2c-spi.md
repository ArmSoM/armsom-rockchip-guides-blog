# Оверлеи Device Tree для GPIO, I2C и SPI на RK3576 и RK3588

Осознанно используйте оверлеи и pin control при расширении систем ArmSoM RK3576 или RK3588.

![Схема рабочего процесса: Оверлеи Device Tree для GPIO, I2C и SPI на RK3576 и RK3588](/assets/004-device-tree-overlays-gpio-i2c-spi-flow.svg)

## Что помогает решить эта статья

Device Tree описывает аппаратное намерение. Не переназначайте вывод GPIO до проверки альтернативных функций и электрических ограничений. Это инженерный workflow, а не замена схеме, release notes или требованиям безопасности для конкретного изделия и ревизии ArmSoM.

## Контекст платформы

Таблицы ArmSoM показывают несколько функций сигналов 40-pin; документация Linux объясняет разрешение оверлеев поверх базового дерева. На практике фиксируйте вместе плату, версию BSP/образа, ревизию периферии, питание и воспроизводимые команды. Так полевые проблемы остаются диагностируемыми, а рабочая лабораторная конфигурация не превращается в скрытую зависимость.

## Воспроизводимая отправная точка

Сначала проверьте руководство для конкретной платы, версию образа и подключение интерфейса, затем выполните минимальную проверку. Сохраняйте вывод команд, версию ядра и образа, ревизию платы и идентификаторы периферии.

## Устранение неполадок

**Симптом: ожидаемое устройство или поведение отсутствует.** Сверьте running image и Device Tree с документацией изделия, затем проверьте питание, направление кабеля, посадку разъема и boot logs.

**Симптом: команда существует, но результат неверный.** Не принимайте пример команды за проверенную конфигурацию изделия. Проверьте pinmux, драйверы, device nodes, права и версии software stack для конкретной платы.

**Симптом: конфигурация пропадает после перезагрузки.** Определите, где должно находиться изменение: в образе, boot configuration, Device Tree, service definition или временной команде. Сохраните serial log и минимальный reproduction.
