Статья полностью передаёт техническую часть RK-YH-YF-501 «Factory Test Tool Instructions» V3.0. В исходнике указаны совместимость с Android 4.4 и новее и поддержка Android Q, однако вход через калькулятор отнесён к V4.0; это расхождение сохранено. Для ArmSoM материал служит справкой по платформе Rockchip Android SDK: проверьте плату, SoC, BSP, версии инструмента и ядра. Светодиоды, клавиши и Framework требуют адаптации; испытания на ArmSoM не проводились. Все три иллюстрации взяты из китайского PDF; отдельных английских изображений нет. См. [официальную документацию ArmSoM](https://docs.armsom.org/).

## 1 Обзор

Инструмент проверяет устройства на производстве и стабильность при длительном прогоне. USB-накопитель или SDCard запускает проверку PCBA либо готового устройства с полной прошивкой. Функциональные тесты: WIFI, BT, LAN, SD, USB, HDMI, левый/правый аудиоканал, клавиши, LED, CVBS. Нагрузочные тесты: Cpu, Vpu, Gpu, Memory.

## 2 Функциональные тесты

### 2.1 Интерфейс

![Интерфейс функциональных тестов, китайский оригинал, с. 6.](/docs/rockchip-box-factory-test-tool/images/cn-p006-1.png)

Интерфейс функциональных тестов, китайский оригинал, с. 6.

### 2.2 Настройка

Создайте `Factory_Test.ini`. Значение `activated = 0` отключает тест, `1` включает. Каждый тест поддерживает клавишу повторения `test_key`: например, `test_key = 1` повторяет неудачные проверки по клавише 1 пульта. Параметры и исходные комментарии ниже сохранены, включая повторяющиеся косые черты.

```ini
[WIFI]
activated = 1 //是否启用该测试项，1：开启， 0：禁用
wifi_ap = zhangwen //测试使用的 Wifi Ap 名称
password = //Wifi Ap 密码
connect = 1 //是否连接 wifi 测试，1：连接 AP, 0：不连接
db_start = -30 //信号强度范围
db_end = -70 //信号强度范围

[BT]
activated = 1 //是否启用该测试项，1：开启， 0：禁用
bt_name = //配置指定蓝牙名称，默认为空

[LAN]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
[SD]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
[USB]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
[HDMI]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
[CHNL]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
[LED]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
[REST]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
[CVBS]
activated = 1 ////是否启用该测试项，1：开启， 0：禁用
```

Параметры WIFI: `wifi_ap` — имя AP, `password` — пароль; `connect = 1` подключается к AP, `0` не подключается. `db_start` и `db_end` задают диапазон уровня сигнала. `bt_name` задаёт имя Bluetooth-устройства, по умолчанию пустое. `CHNL` — левый/правый канал; `REST` — исходное имя раздела проверки RESET.

### 2.3 Шифрование конфигурации

Запустите `EncryptTool` из каталога `EncryptTool`, нажмите «Encrypt» и выберите `Factory_Test.ini`. Рядом создаётся `Factory_Test_Signed.bin`; переименуйте его в `Factory_Test.bin`.

![EncryptTool, китайский оригинал, с. 8.](/docs/rockchip-box-factory-test-tool/images/cn-p008-1.png)

EncryptTool, китайский оригинал, с. 8.

### 2.4 Запуск функционального теста

Скопируйте `Factory_Test.bin` в корень SDCard или USB-накопителя. Вставка носителя автоматически запускает проверку.

### 2.5 Поведение тестов

| Тест | Оценка и примечания |
|---|---|
| Wifi | Автоматически ищет заданную AP, при соответствующей настройке подключается, определяет и показывает результат; причина отказа выводится в примечаниях. |
| Bluetooth | Автоматически ищет Bluetooth-устройства. При заданном имени необходимо найти именно его; иначе достаточно любого устройства. Результат отображается в интерфейсе. |
| Lan | Автоматически получает IP-адрес для определения и отображения результата. |
| SDCard | Автоматически проверяет чтение/запись файлов и показывает результат. |
| USB | Автоматически проверяет чтение/запись; для нескольких USB-портов отдельные результаты перечислены в примечаниях. |
| HDMI | Вручную оцените автоматически воспроизводимое видео. Нормальное изображение без полос и прочих дефектов означает успех. Файл по умолчанию: `/sdcard/Aging_Test_Video.mp4`. |
| CVBS | Вручную проверьте, что при автоматическом переходе к CVBS экран HDMI гаснет, а CVBS показывает изображение. |
| CHNL | Проверьте на слух: мужской голос слева и женский справа означают успех. |
| LED | Вручную проверьте регулярное мигание LED. Функция зависит от изделия: добавьте управляющий узел LED в ядре либо задайте его путь в `persist.sys.leds_path`. |
| RESET | Удерживайте RESET на обратной стороне платы. При успехе диалог исчезает и появляется результат. Требуется настройка сопоставления клавиш для изделия. |

По умолчанию интерфейс показывает Mac-адрес Ethernet.

## 3 Нагрузочный прогон

### 3.1 Интерфейс

![Интерфейс прогона, китайский оригинал, с. 11.](/docs/rockchip-box-factory-test-tool/images/cn-p011-1.png)

Интерфейс прогона, китайский оригинал, с. 11.

### 3.2 Настройка

Создайте `Aging_Test.ini`. Блокировка задаёт необходимость успешного функционального теста. Для массового производства включите видео в прошивку в `system/usr/` или `/sdcard/`, чтобы не копировать их на множество USB-накопителей или SDCard.

В тексте сказано, что начиная с V4.0 ввод `000.=` в калькуляторе Android открывает экран прогона. Это расходится с V3.0 на обложке; проверьте фактический инструмент. Видео должно существовать заранее, иначе VPU-тест не запустится. По умолчанию используются `/sdcard/Aging_Test_Video.mp4` и `/sdcard/Aging_Test_Video_Float.mp4`; файлы в `system/usr/` имеют приоритет.

```ini
[FactoryTest]
required = 0 ////是否必须要通过功能测试后，才能进行老化测试。
///// 1：必须通过功能测试， 0：不必通过功能测试
```

`required = 1` требует успешного функционального теста; `0` не требует.

### 3.3 Шифрование

Используйте процедуру функционального теста; итоговый файл — `Aging_Test.bin`.

### 3.4 Запуск прогона

Поместите `Aging_Test.bin` в корень SDCard/USB-накопителя и вставьте носитель. Красный и зелёный LED мигают вместе при запуске. Через шесть секунд после аварийного выхода программы оба горят постоянно; при ошибке теста оба гаснут. Индикация требует настройки для изделия.

### 3.5 Выход

Во избежание случайного выхода с пульта используйте HOME для возврата на рабочий стол. Это не универсальная функция: нужны согласованные изменения SDK Framework.

## 4 Запись серийного номера

### 4.1 Настройка

Создайте `SN_Test.ini`. `adb_enable = 1` включает ADB, `0` отключает.

```ini
[ADB]
adb_enable = 1 //开启或关闭 ADB 1：开启，0：关闭
```

### 4.2 Шифрование

По процедуре функционального теста сформируйте `SN_Test.bin`.

### 4.3 Включение записи

Поместите `SN_Test.bin` в корень SDCard/USB-накопителя. Вставка включает ADB для внешнего инструмента записи номера. Номер записывает другой инструмент; данная операция лишь включает ADB и может быть расширена.

**Если все три файла конфигурации лежат на одном USB-накопителе, по умолчанию запускается только функциональный тест.**
