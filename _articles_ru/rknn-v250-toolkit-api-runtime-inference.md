## 7 Инициализация среды выполнения и инференс

<!-- source EN p19 unit 98 -->

### 7.1 Загрузка модели RKNN

<!-- source EN p19 unit 99 -->

| API | load_rknn |
| --- | --- |
| Описание | Загрузить модель RKNN.<br>После загрузки не требуется выполнять настройку модели, загрузку исходной модели и сборку RKNN. Загруженную модель можно использовать только при подключении к аппаратной NPU для инференса или получения данных производительности. Симулятор и анализ точности недоступны. |
| Параметр | path: Путь к файлу модели RKNN. |
| Возвращаемое значение | 0: Загрузка выполнена успешно. |
| Возвращаемое значение | -1: Ошибка загрузки. |

<!-- source EN p19 unit 100 -->

Пример кода:

<!-- source EN p19 unit 101 -->

```python
# Load the mobilenet_v1 RKNN model in the current path
ret = rknn.load_rknn(path='./mobilenet_v1.rknn')
```

### 7.2 Инициализация среды выполнения

<!-- source EN p19 unit 103 -->

Перед инференсом или оценкой производительности инициализируйте среду выполнения. Интерфейс определяет её тип: аппаратная платформа или программный симулятор.

<!-- source EN p19 unit 104 -->

| API | init_runtime |
| --- | --- |
| Описание | Инициализировать среду выполнения. |
| Параметр | target: Целевая аппаратная платформа. Поддерживаются 'rv1103', 'rv1103b', 'rv1106', 'rv1106b', 'rv1126b', 'rk3562', 'rk3566', 'rk3568', 'rk3576' и 'rk3588'. По умолчанию "None": модель работает в симуляторе.<br>Примечание: при target = None сначала нужно вызвать build или hybrid_quantization. |
| Параметр | device_id: Идентификатор устройства. При подключении нескольких устройств к ПК нужно указать этот параметр; его можно получить через list_devices. По умолчанию None. |
| Параметр | perf_debug: Режим отладки при оценке производительности. В нём можно получить время выполнения каждого слоя; иначе доступно только полное время выполнения модели. По умолчанию False. |
| Параметр | eval_mem: Включить ли режим оценки памяти. При True затем можно вызвать eval_memory для получения потребления памяти при выполнении модели. По умолчанию False. |
| Параметр | async_mode: Использовать ли асинхронный режим. По умолчанию False.<br>Вызов inference включает установку входного изображения, выполнение модели и получение результата. В асинхронном режиме установка входа текущего кадра выполняется одновременно с инференсом предыдущего. Поэтому, кроме первого кадра, время установки входа каждого следующего кадра скрывается, что повышает производительность. Каждый возвращаемый результат в этом режиме относится к предыдущему кадру. (Пока не поддерживается.) |
| Параметр | core_mask: Выбирает ядра NPU во время выполнения. Поддерживаются RK3588 / RK3576 и следующие конфигурации:<br>RKNN.NPU_CORE_AUTO: автоматическое планирование, модель выполняется на свободном ядре NPU.<br>RKNN.NPU_CORE_0: выполнение на NPU0.<br>RKNN.NPU_CORE_1: выполнение на NPU1.<br>RKNN.NPU_CORE_2: выполнение на NPU2.<br>RKNN.NPU_CORE_0_1: одновременное выполнение на NPU0 и NPU1.<br>RKNN.NPU_CORE_0_1_2: одновременное выполнение на NPU0, NPU1 и NPU2.<br>RKNN.NPU_CORE_ALL: число используемых ядер определяется платформой.<br>По умолчанию "RKNN.NPU_CORE_AUTO".<br>Примечание: у RK3576 только 2 ядра, поэтому NPU_CORE_2 и NPU_CORE_0_1_2 задавать нельзя. |
| Параметр | fallback_prior_device: Приоритетное резервное устройство для OP, не поддерживаемого NPU. Поддерживаются 'gpu' и 'cpu'; 'gpu' действует только на платформах с аппаратной GPU. По умолчанию 'cpu'. |
| Возвращаемое значение | 0: Среда выполнения инициализирована успешно. |
| Возвращаемое значение | -1: Ошибка инициализации среды выполнения. |

<!-- source EN p20 unit 106 -->

Пример кода:

<!-- source EN p20 unit 107 -->

```python
# Initialize the runtime environment
ret = rknn.init_runtime(target='rk3566')
```

### 7.3 Регистрация пользовательского оператора

<!-- source EN p20 unit 109 -->

Интерфейс регистрирует пользовательский оператор.

<!-- source EN p20 unit 110 -->

| API | reg_custom_op |
| --- | --- |
| Описание | Зарегистрировать пользовательский оператор; поддерживается только для модели ONNX. |
| Параметр | custom_op: Класс пользовательского оператора для создания нового OP вне спецификации операторов ONNX. Рекомендуется начинать op_type нового OP с 'cst'; пользователь должен реализовать функции shape_infer и compute.<br>Примечание: класс custom_op используется только при преобразовании модели и генерации моделей RKNN с пользовательскими операторами. Для развёртывания на устройстве также следует обратиться к главе 5.5 'RKNN SDK User Guide'. |
| Возвращаемое значение | 0: Успешно. |
| Возвращаемое значение | -1: Ошибка. |

<!-- source EN p21 unit 111 -->

Пример кода:

<!-- source EN p21 unit 112 -->

```python
import numpy as np
from rknn.api.custom_op import get_node_attr
class cstSoftmax:
    op_type = 'cstSoftmax'
    def shape_infer(self, node, in_shapes, in_dtypes):
        out_shapes = in_shapes.copy()
        out_dtypes = in_dtypes.copy()
        return out_shapes, out_dtypes
    def compute(self, node, inputs):
        x = inputs[0]
        axis = get_node_attr(node, 'axis')
        x_max = np.max(x, axis=axis, keepdims=True)
        tmp = np.exp(x - x_max)
        s = np.sum(tmp, axis=axis, keepdims=True)
        outputs = [tmp / s]
        return outputs

ret = rknn.reg_custom_op(cstSoftmax)
```

### 7.4 Инференс модели RKNN

<!-- source EN p21 unit 114 -->

Интерфейс запускает инференс модели RKNN и получает его результат.

<!-- source EN p21 unit 115 -->

| API | inference |
| --- | --- |
| Описание | Выполнить инференс модели с указанными входами и получить результат.<br>Если при инициализации среды target задан как Rockchip NPU, инференс выполняется на указанной аппаратной платформе. Если target не задан, используется симулятор. |
| Параметр | inputs: Список входов для инференса. Тип объектов — ndarray. |
| Параметр | data_format: Список раскладок входных данных: "nchw" или "nhwc"; действует только для 4-мерных входов. По умолчанию None: все входы имеют раскладку "nhwc". |
| Параметр | inputs_pass_through: Флаг pass_through. По умолчанию None: все входы передаются без режима pass_through.<br>Без pass_through инструментарий перед передачей входа драйверу NPU вычитает среднее, делит на дисперсию и т. п.; в режиме pass_through эти операции не выполняются.<br>Параметр — список. Например, чтобы включить сквозную передачу для input0, но не для input1, задают [1, 0]. |
| Возвращаемое значение | results: Результат инференса в формате списка ndarray. |

<!-- source EN p21 unit 116 -->

Пример кода:

<!-- source EN p21 unit 117 -->

Для классификационной модели, например mobilenet_v1, пример кода приведён ниже; полный код см. в example/tfilte/mobilenet_v1. Написание tfilte сохранено из исходника.

```python

outputs = rknn.inference(inputs=[img])
```

## Источник и редакционные примечания

Технические главы разделены по назначению. Код, идентификаторы и параметры сохранены. Китайская версия следует китайскому оригиналу; английская, русская и немецкая — английскому. В главы без иллюстраций вымышленные изображения не добавлены.

Примечания: журналы с SDK 1.5.2 сохранены как исторические примеры, а не измерения V2.5.0. Ячейка Python для Ubuntu20.04 различается: китайский текст 3.8/3.9, английский 3.8/3.8; аналогично для Debian11; в разделе ARM64 Debian всё ещё помечен x64. Значения сохранены; проверяйте фактический установочный пакет. V2.5.0 добавляет главу C++ codegen и уточняет квантование и стратегии памяти; параметры старой версии не подменяют новый источник.
