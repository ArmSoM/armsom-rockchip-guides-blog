# Запуск нескольких дисплеев DRM KMS на Rockchip RK3588 и RK3576

Поднимайте дисплеи с учетом модели Linux DRM, состояния коннектора и маршрутизации Device Tree.

![Схема рабочего процесса: Запуск нескольких дисплеев DRM KMS на Rockchip RK3588 и RK3576](/assets/007-drm-kms-multi-display-flow.svg)

## Что помогает решить эта статья

Раздельно проверяйте физический link, mode setting и compositor, чтобы не сводить любой черный экран к одной причине. Это инженерный workflow, а не замена схеме, release notes или требованиям безопасности для конкретного изделия и ревизии ArmSoM.

## Контекст платформы

Руководства ArmSoM содержат примеры дисплеев и оверлеев. Доступность разъемов определяется конкретной платой, даже при общем display subsystem SoC. На практике фиксируйте вместе плату, версию BSP/образа, ревизию периферии, питание и воспроизводимые команды. Так полевые проблемы остаются диагностируемыми, а рабочая лабораторная конфигурация не превращается в скрытую зависимость.

## Воспроизводимая отправная точка

Сначала проверьте руководство для конкретной платы, версию образа и подключение интерфейса, затем выполните минимальную проверку. Сохраняйте вывод команд, версию ядра и образа, ревизию платы и идентификаторы периферии.

```bash
modetest -c
cat /sys/class/drm/card0-*/status
# Then test a documented mode with the image's DRM tools
```

## Устранение неполадок

**Симптом: ожидаемое устройство или поведение отсутствует.** Сверьте running image и Device Tree с документацией изделия, затем проверьте питание, направление кабеля, посадку разъема и boot logs.

**Симптом: команда существует, но результат неверный.** Не принимайте пример команды за проверенную конфигурацию изделия. Проверьте pinmux, драйверы, device nodes, права и версии software stack для конкретной платы.

**Симптом: конфигурация пропадает после перезагрузки.** Определите, где должно находиться изменение: в образе, boot configuration, Device Tree, service definition или временной команде. Сохраните serial log и минимальный reproduction.
