## 3. Архитектура

Для упрощения переноса Rockit в ядре разработана новая библиотека времени выполнения, далее RRT. Её структура показана ниже.

![Руководство по библиотеке Rockchip Rockit Runtime - RRT](/docs/rockchip-rockit-runtime/assets/en-p004-figure-01.png)



```text
.
├── isp.ko   ---- isp - модуль, узел /dev/mpi/rkisp-vir0
├── valloc.ko  --- менеджер буферов, узел /dev/mpi/valloc
├── venc.ko    --- Кодировщик - модуль, узел /dev/mpi/venc
├── vmpi.ko    --- медиасреда, узел /dev/mpi/vmpi
├── vpss.ko    --- vpss - модуль, узел /dev/mpi/vpss
├── vrga.ko    --- rga - модуль, узел /dev/mpi/vrga
├── vrgn.ko    --- rgn - модуль, узел /dev/mpi/vrgn
├── vsys.ko    --- system - модуль, узел /dev/mpi/vsys
└── vvi.ko     --- vi - модуль, узел /dev/mpi/vvi
```



Перед использованием интерфейсов rockit необходимо загрузить перечисленные модули ko. Все эти модули объединены в один ko, который загружается следующей командой:



```text
insmod rockit.ko
```



Проверьте успешную загрузку следующей командой:



```text

```



После успешной загрузки можно запускать программы, зависящие от rockit.so.

### 3.1 Параметры модуля KO

#### 3.1.1 mcu_fw_path

Путь к прошивке MCU для режима wrapping. По умолчанию пустой: прошивка MCU не загружается.



```text
insmod rockit.ko mcu_fw_path=/oem/usr/ko/hpmcu_wrap.bin
```



#### 3.1.2 mcu_fw_addr

Адрес прошивки MCU для wrapping. По умолчанию 0xff6ff000 для RV1106 и 0x210f6000 для RV1103B.



```text
insmod rockit.ko mcu_fw_addr=0xff6ff000
```



#### 3.1.3 isp_max_h

Высота входа перед ISP. Если VICAP выполняет обрезку, источник предписывает настроить «ширину после обрезки». Это противоречит определению высоты и требует проверки по SDK. При неверной настройке cat /dev/mpi/vlog выводит правильное значение. Диагностическая строка:

```text
mpi_log_err("isp input height config err, config h= %d, real h = %d", isp_max_h, isp_h);
```





```text
insmod rockit.ko isp_max_h=1920
```



#### 3.1.4 isp_max_w

Зарезервировано.

#### 3.1.5 en_mcu

Включение драйвера MCU. По умолчанию включён на RV1106 и выключен на RV1103B. Если отключён, драйвер MCU не загружается.



```text
insmod rockit.ko en_mcu=0
```



#### 3.1.6 rk_dma_heap_base

Начальный адрес MMZ, освобождаемой через RK_MPI_SYS_RelasePhyMemory, должен быть выровнен по 4K и превышать начало MMZ. Начало MMZ = общий объём физической памяти - размер MMZ.



```text
insmod rockit.ko rk_dma_heap_base=0x40000
```



#### 3.1.7 rk_dma_heap_size

Размер MMZ, освобождаемой через RK_MPI_SYS_RelasePhyMemory, не должен превышать размер MMZ.



```text
insmod rockit.ko rk_dma_heap_size=0x40000
```



## 4. Межплатформенный перенос

RRT дополнена уровнем абстракции ОС OSAL и переписана на его основе. Теперь она работает в ядре Linux, в пользовательском режиме Linux и в RTOS. На RV1103B/RV1126B работают два экземпляра RRT: один в пользовательском режиме и один в ядре. Для просмотра узлов /dev/mpi/xxx в пользовательском режиме Linux и в RTOS добавьте dumpsys перед исходной командой:

```text
dumpsys cat /dev/mpi/valloc
dumpsys cat /dev/mpi/vsys
dumpsys cat /dev/mpi/vlog
dumpsys cat /dev/mpi/vrgn
```



## 5. Межплатформенное взаимодействие

На одном SoC могут работать несколько RRT. Для упрощения взаимодействия разработчиков модулей RRT поддерживает связь между платформами: VALLOC управляет межплатформенными счётчиками ссылок BUFFER, а VSYS обеспечивает связывание и передачу BUFFER. Обязательное условие: RRT разных платформ должны совместно использовать BUFFER через физическую память. Ниже перечислены поддерживаемые на SoC экземпляры RRT и их модули.

| SOC | RRT (режим ядра Linux) | RRT (пользовательский режим Linux) | RRT (rt-thread) |
| --- | --- | --- | --- |
| RV1106/RV1103 | VI / VPSS / VENC / AVS /<br>VRGN / VALLOC / VSYS | Не поддерживается | Не поддерживается |
| RV1103B/RV1106B | VI / VPSS / VENC / AVS /<br>VRGN / VALLOC / VSYS | VDEC / VO / VRGN / AI / AO /<br>AENC / ADEC / AMIX / AF / TDE /<br>VALLOC / VSYS / TDE | Не поддерживается |
| RK3308 | Не поддерживается | VALLOC / VSYS / VRGN / VDEC / AI<br>/ AO / ADEC / AENC / AMIX / AF /<br>VO | Не поддерживается |
| RK3506 | Не поддерживается | VALLOC / VSYS / VRGN / VDEC / AI<br>/ AO / ADEC / AENC / AMIX / AF /<br>VO / TDE | VALLOC / VSYS / VRGN / VDEC /<br>AI / AO / ADEC / AENC / AMIX /<br>AF / VO / TDE |
| RV1126B | VI / VPSS / VENC / AVS /<br>VRGN / VALLC / VSYS /<br>GDC / IVS | VI / VALLOC / VSYS / VRGN / VDEC<br>/ AI / AO / ADEC / AENC / AMIX /<br>AF / VO / TDE | Не поддерживается |

## 7. VLOG

Менеджер журналов медиасреды.

### 7.1 Просмотр журнала ядра



```text
cat /dev/mpi/vlog
```



### 7.2 Настройка уровня журналирования модуля

Команда `echo module=level > /tmp/rt_log_level` меняет уровень журналирования модуля одновременно для rockit so и ko. Допустимые module: all cmpi mb sys vdec venc rgn vpss vgs tde avs wbc vo vi ai ao aenc adec. Уровни: 0,1,2,3,4,5,6; 2 - ERR (красный), 3 - WRN (жёлтый), 4 - INF (зелёный).

```text
echo module=level > /tmp/rt_log_level
```



### 7.3 Путь и размер журнала SO



```text
echo rt_log_path=/tmp/rockit.log > /tmp/rt_log_level

echo rt_log_size=1024000 > /tmp/rt_log_level
```



### 7.4 Очистка журнала



```text
echo 0 > /dev/mpi/vlog
```

## 10. Соответствие venc_info и API rockit

venc_info содержит параметры кодировщика, выводимые ядром. Поддерживаются только RV1103B/RV1106B и RV1103/RV1106. Эта глава систематизирует ключевые настройки, влияющие на субъективное качество изображения и объективную степень сжатия.

| venc_info | API rockit | Поле API rockit | Примечание |
| --- | --- | --- | --- |
| qbias_en<br>qbias_i<br>qbias_p | RK_MPI_VENC_SetH264Qbias<br>RK_MPI_VENC_SetH265Qbias | bEnable<br>u32QbiasI<br>u32QbiasP | RV1103/RV1106 поддерживается; RV1103B/RV1106B не поддерживается |
| qbias_en<br>qbias_arr[18] | RK_MPI_VENC_SetH264Qbias2<br>RK_MPI_VENC_SetH265Qbias2 | bEnable<br>u32Qbias2[18] | RV1103/RV1106 не поддерживается; обновлённая версия для RV1103B/RV1106B |

## Расхождения источников и проверка

- Оба источника имеют версию V2.28.0 и дату 2025-04-27. В китайском дополнительно есть `memtype` и `nkid`; они включены во все языки. Число страниц само по себе не определяет актуальность.
- VSYS `table`: в китайском размер равен частоте кадров, n сохраняет n кадров, 0 отбрасывает; в английском 0 сохраняет, 1 отбрасывает. В основном тексте используется китайская трактовка; противоречие требует проверки по SDK.
- `isp_max_h` определён как высота входа, но оба источника говорят о «ширине после обрезки». Проверьте реализацию SDK и исходную диагностическую строку; размерность не исправлена молча.
- В списке модулей ядра RV1126B сохранено `VALLC`; сохранены также `cenalbe`, `SCALL` и `RK_MPI_SYS_RelasePhyMemory`. Китайские `last_runing`, `runing`, `heigth` соответствуют английским `last_running`, `running`, `height`; обе формы указаны у полей.
- В обеих таблицах API `qp_dlt_row_i` соответствует `u32RowQpDelta`, а `qp_dlt_row` - `u32RowIQpDelta`. Возможное противоречие смыслу I/P не исправлено перестановкой полей.
- Китайские заголовки различают `mpp_packet pool` и `mpp_buffer pool`; английский дважды использует `mpp_buffer pool`. Здесь приняты китайские заголовки, сохранены все три таблицы: packet, buffer и frame.
- Английский текст добавляет для VRGN `h x y` «всего 8 групп»; это сохранено во всех языках. Для `wcnt` китайский указывает число кадров, английский - частоту; принято число кадров. Для `min_size` принято китайское «минимальное свободное место для одного кадра», а не английское «последнее».
- Английское Warp трактуется по китайскому как wrapping; идентификаторы не меняются. Сохранены уточнения о макроблоках ROI, компенсации среднего при SAD, крайне низком битрейте статичной сцены, устранении шлейфов и дрожания/ползания шума.
