## 1 Обзор

<!-- Source EN PDF p.9, block 1 -->

Модули цветовой настройки ISP30 включают автоматический баланс белого AWB, цветокоррекцию CC и трёхмерную таблицу поиска 3dlut.

<!-- Source EN PDF p.9, block 2 -->

Модули CCM и 3DLUT ISP21 (RK3566/RK3568) и ISP20 (RV1126/RV1109) не различаются; при настройке AWB нужно учитывать следующее:

<!-- Source EN PDF p.9, block 3 -->

(1) ISP21 не поддерживает настройку нескольких подокон Multiwindow.

<!-- Source EN PDF p.9, block 4 -->

(2) Алгоритм 3dyuv обновлён.

<!-- Source EN PDF p.9, block 5 -->

(3) Дополнительная область позволяет только исключать белые точки, но не использовать их как дополнительный источник.

<!-- Source EN PDF p.9, block 6 -->

(4) Добавлены разные веса белых точек в зависимости от яркости.

<!-- Source EN PDF p.9, block 7 -->

(5) Добавлены веса блоков.

<!-- Source EN PDF p.9, block 8 -->

(6) В XY для каждого источника задаются два размера области, на один меньше, чем в ISP20.

<!-- Source EN PDF p.9, block 9 -->

Модули CCM и 3DLUT ISP30 (RK3588) и ISP21 (RK3566/RK3568) не различаются, но для 3DLUT добавлены инструменты (см. описание модуля). Различия настройки AWB:

<!-- Source EN PDF p.9, block 10 -->

(1) Дополнительная область поддерживает как исключение белых точек, так и дополнительный источник.

<!-- Source EN PDF p.9, block 11 -->

(2) В инструменте обновлена настройка порогов YUV (см. пример 2).

## 2 AWB

<!-- Source EN PDF p.9, block 13 -->

### 2.1 Описание функции

<!-- Source EN PDF p.9, block 14 -->

Автоматический баланс белого рассчитывает WB gain каналов R/G/B и умножает на него RGB, восстанавливая чистый белый из белого, изменённого освещением. Это согласует цвет изображения с реальным цветом объекта при разных источниках света. При наличии белых точек WB gain вычисляется по их автоматическому обнаружению, при отсутствии — методом однотонных цветов. Хроматическая адаптация изменяет цель коррекции для соответствия восприятию человека; настройка тона меняет общий оттенок по предпочтению. AWB состоит из аппаратной статистики и программной стратегии, показанных на схеме.

#### 2.2.4 hdrPara

Соответствует autoPara.hdrPara. Для HDR Sensor можно выбрать длинный, средний или короткий кадр для статистики баланса белого; рекомендуется автоматический режим.

<!-- Source EN PDF p.12, block 31 -->

| Имя | Описание |
|---|---|
| frameChooseMode | CALIB_AWB_INPUT_RAW_FIXED, CALIB_AWB_INPUT_RAW_AUTO, CALIB_AWB_INPUT_BAYERNR либо CALIB_AWB_INPUT_DRC. RAW_FIXED фиксирует длинный/короткий raw через frameChoose; RAW_AUTO выбирает их автоматически; BAYERNR использует выход bayer2dnr; DRC — выход DRC. |

#### 2.2.5 limitRange

<!-- Source EN PDF p.12, block 33 -->

(1) autoPara.limitRange в JSON задаёт диапазон пикселей для статистики белых точек; остальные не учитываются. Расширение диапазона увеличивает число точек; для повышения точности исключают слишком тёмные и слишком светлые. Диапазоны задаются для разных уровней освещения, фактический получается линейной интерполяцией.

<!-- Source EN PDF p.13, block 34 -->

| Имя | Описание |
|---|---|
| lumaValue | Освещённость в диапазоне 0-255000. |
| maxR | Верхняя граница R; рекомендуется 255-black level-3, максимум 255. |
| minR | Нижняя граница R; рекомендуется 3, минимум 0. |
| maxG | Верхняя граница G; рекомендуется 255-black level-3, максимум 255. |
| minG | Нижняя граница G; рекомендуется 3, минимум 0. |
| maxB | Верхняя граница B; рекомендуется 255-black level-3, максимум 255. |
| minB | Нижняя граница B; рекомендуется 3, минимум 0. |
| maxY | Верхняя граница Y; рекомендуется 255-black level-3, максимум 255. |

##### 2.2.11.5 Обнаружение белых точек RYUV

<!-- Source EN PDF p.18, block 77 -->

Вычисляется разность яркости точки сцены (y0,u0,v0) и теоретической белой точки (y',u0,v0): diff = \|y0-y'\|. При diff < th точка считается белой, иначе — нет. Для разных положений по u можно задать разные th, как на ломаной dis-th.

<!-- Source EN PDF p.18, block 78 -->

![Рисунок английского исходника, PDF p.18, #78](/docs/rockchip-isp30-color-optimization/assets/en-p18-figure1.png)

*Рисунок английского исходника, PDF p.18, #78.*

<!-- Source EN PDF p.18, block 79 -->

В инструменте калибровки по diff и u точек сцены (y0,u0,v0) настраивается ломаная u-th соответствующего источника для правильного определения белых точек и исключения небелых (в исходнике указано, что функция пока не реализована). Источник определяется методами XY/UV, поэтому YUV нельзя включать отдельно: требуется совместное использование с XY или UV.

<!-- Source EN PDF p.18, block 81 -->

Соответствует autoPara.lightSources.rtYuvRegion в JSON.

<!-- Source EN PDF p.19, block 82 -->

#### 2.2.18 Сглаживание WBGain

<!-- Source EN PDF p.34, block 179 -->

Вычисляется вес усиления баланса белого предыдущего кадра wbGainDampFactor. Взвешивание wbgain предыдущего и текущего кадров сглаживает изменение. Увеличение dFMin и dFMax повышает стабильность, но замедляет сходимость; уменьшение ускоряет сходимость, однако может вызвать скачки wbgain.

<!-- Source EN PDF p.34, block 180 -->

Логика вычисления wbGainDampFactor: при небольшом изменении освещённости wbGainDampFactor стабилизируется на dFMax; при резком изменении приближается к dFMin. Вес текущего кадра увеличивается, чтобы wbgain быстрее следовал изменениям среды и ускорял сходимость. Код приведён ниже:

<!-- Source EN PDF p.34, block 181 -->

```text
if (varianceLuma > LvVarTh) {
*wbGainDampFactor -= dFStep;
}
else {
*wbGainDampFactor += dFStep;
}
if (*wbGainDampFactor < dFMin) {
*wbGainDampFactor = dFMin;
}
else if (*wbGainDampFactor > dFMax) {
*wbGainDampFactor = dFMax;
}
```

<!-- Source EN PDF p.34, block 193 -->

Соответствует структуре autoExtPara.dampFactor в JSON.

<!-- Source EN PDF p.35, block 194 -->

| Имя | Описание |
|---|---|
| dFStep | Шаг изменения wbGainDampFactor, 0-1. |
| dFMin | Минимум wbGainDampFactor, 0-1. |
| dFMax | Максимум wbGainDampFactor, 0-1. |
| LvIIRsize | Число кадров записи освещённости, 0-255. |
| LvVarTh | Порог дисперсии освещённости для изменения wbGainDampFactor, 0-255000. |

## 3 Базовая коррекция цвета CCM

<!-- Source EN PDF p.62, block 419 -->

### 3.1 Описание функции

<!-- Source EN PDF p.62, block 420 -->

Спектральная характеристика датчика не может точно совпасть с откликом человеческого зрения. Матрица цветокоррекции CCM корректирует перекрёстное влияние и интенсивность спектрального отклика, приближая цвет захваченного изображения к человеческому восприятию.

<!-- Source EN PDF p.62, block 421 -->

Инструмент калибровки CCM поддерживает предварительную калибровку матрицы 3×3 CCM (aij) по 24-полевой мишени.

<!-- Source EN PDF p.62, block 422 -->

![Рисунок английского исходника, PDF p.62, #422](/docs/rockchip-isp30-color-optimization/assets/en-p62-figure1.png)

*Рисунок английского исходника, PDF p.62, #422.*

```text
[R_CC, G_CC, B_CC]^T = [[a11,a12,a13],[a21,a22,a23],[a31,a32,a33]] * [R_camera,G_camera,B_camera]^T
```

<!-- Source EN PDF p.62, block 423 -->

Поддерживаются несколько CCM для разных цветовых температур. Во время работы ISP глобальная или локальная насыщенность изменяется по узлу gain параметров IQ, динамически корректируя коэффициенты CCM.

<!-- Source EN PDF p.62, block 424 -->

![Рисунок английского исходника, PDF p.62, #424](/docs/rockchip-isp30-color-optimization/assets/en-p62-figure2.png)

*Рисунок английского исходника, PDF p.62, #424.*

```text
[R_CC,G_CC,B_CC]^T = alpha * scale * [[a11-1,a12,a13],[a21,a22-1,a23],[a31,a32,a33-1]] * [R_camera,G_camera,B_camera]^T + [R_camera,G_camera,B_camera]^T
```

##### 3.2.3.1 Выбор способа вычисления матрицы CCM

<!-- Source EN PDF p.64, block 445 -->

Модуль CCM использует два способа: (1) выбирает параметры CCM источника с минимальным евклидовым расстоянием между стандартным усилением баланса белого и статистическим значением; (2) взвешивает матрицы CCM вероятностями расстояния между стандартным и статистическим усилениями каждого источника. Вероятность расстояния prob вычисляется следующим образом:

![Векторные формулы вероятности расстояния](/docs/rockchip-isp30-color-optimization/assets/en-p64-vector-formulas.png)

```text
dist = sqrt((Rgain-awbGain[0])^2 * wr + (Bgain-awbGain[1])^2 * wb)
prob = exp(-dist^2 / sigma^2)
```

<!-- Source EN PDF p.64, block 446 -->

Здесь Rgain и Bgain — статистические усиления баланса белого, awbGain — стандартные усиления каждого источника, wr и wb — веса каналов R и B, sigma — стандартное отклонение dist всех источников.

<!-- Source EN PDF p.64, block 447 -->

В узле illu_estim.

### 3.3 Калибровка CCM

##### 3.3.1.1 Выбор источников для калибровки

Шаг 2. Настройте экспозицию так, чтобы ни одно поле после gamma не было переэкспонировано. Рекомендуется автоматическая экспозиция.

##### 3.3.2.2 Диаграммы цветовых различий

<!-- Source EN PDF p.67, block 475 -->

Анализируйте отклонённый компонент по направлению и расстоянию относительно стандартного поля на диаграмме:

### 3.4 Коррекция цвета

<!-- Source EN PDF p.68, block 491 -->

#### 3.4.1 Коррекция общей насыщенности

<!-- Source EN PDF p.68, block 492 -->

##### 3.4.1.1 Настройка gain_alphaScale_curve

<!-- Source EN PDF p.68, block 493 -->

Настраивайте scale в диапазоне [0, 1.0], изменяя итоговую интенсивность цветокоррекции. Меньший scale снижает насыщенность, больший повышает её.

<!-- Source EN PDF p.68, block 494 -->

##### 3.4.1.2 Настройка gains-sat

<!-- Source EN PDF p.68, block 495 -->

Меньший SAT снижает насыщенность, больший повышает её. Для разных источников можно задавать разные параметры.

<!-- Source EN PDF p.68, block 496 -->

##### 3.4.1.3 Добавление CCM высокой насыщенности

<!-- Source EN PDF p.68, block 497 -->

Если максимальные значения первых двух настроек недостаточны, перекалибруйте CCM с большей насыщенностью и установите максимальный sat в gains-sat равным увеличенной насыщенности.

<!-- Source EN PDF p.69, block 498 -->

##### 3.4.1.4 Уменьшение насыщенности тёмных пикселей

<!-- Source EN PDF p.69, block 499 -->

Уменьшение y_alpha_curve снижает насыщенность тёмных пикселей. Последнее значение должно быть 1024, иначе изменится насыщенность пикселей другой яркости.

<!-- Source EN PDF p.69, block 500 -->

#### 3.4.2 Коррекция отдельных цветов

<!-- Source EN PDF p.69, block 501 -->

Если после общей настройки насыщенности цвет не соответствует ожиданиям, попробуйте следующее:

<!-- Source EN PDF p.69, block 502 -->

(1) Для соответствия человеческому зрению сначала проверьте правильность баланса белого.

<!-- Source EN PDF p.69, block 503 -->

(2) Для совпадения с эталонной камерой сначала проверьте совпадение баланса белого.

<!-- Source EN PDF p.69, block 504 -->

(3) Для совпадения с эталонной камерой также проверьте близость яркости.

<!-- Source EN PDF p.69, block 505 -->

(4) Если баланс белого согласован либо правилен, а яркость близка, но цвет всё ещё не устраивает, измените параметры CCM.

<!-- Source EN PDF p.69, block 506 -->

##### 3.4.2.1 Проверка правильности баланса белого

<!-- Source EN PDF p.69, block 507 -->

Главное: имеет ли белый объект цветовой оттенок.

<!-- Source EN PDF p.69, block 508 -->

Методы:

<!-- Source EN PDF p.69, block 509 -->

Визуально проверьте, выглядит ли белый объект в видео белым.

<!-- Source EN PDF p.69, block 510 -->

##### 3.4.2.2 Согласование баланса белого с эталонной камерой

<!-- Source EN PDF p.69, block 512 -->

<!-- Source EN PDF p.69, block 513 -->

(2) Если эталонная камера заметно окрашивает белый объект, а баланс RK сравнительно правилен, выясните, вызвано ли это недостатком алгоритма либо иной тональной настройкой. <!-- Source EN PDF p.69, block 514 -->

(3) Как отличить недостаток алгоритма от цветовых предпочтений эталонной камеры:

<!-- Source EN PDF p.69, block 515 -->

a. Если сцена содержит только белые объекты при подходящей яркости, но эталонная камера даёт оттенок, скорее всего, применена тональная настройка.

<!-- Source EN PDF p.69, block 516 -->

b. В противном случае оригинал относит это к недостатку алгоритма эталонной камеры.

## 4 Расширенная коррекция цвета 3DLut

<!-- Source EN PDF p.76, block 630 -->

### 4.1 CCM и 3DLut

<!-- Source EN PDF p.76, block 631 -->

CCM приближает цвет при разных источниках к человеческому зрению; 3DLut изменяет отдельные цвета согласно предпочтениям. Преимущества и недостатки обоих способов:

<!-- Source EN PDF p.76, block 632 -->

|  | CCM | 3DLut |
|---|---|---|
| Преимущества | Естественные переходы цвета, малая вероятность появления шума. | Проще корректировать тон и насыщенность отдельного цвета, не затрагивая остальные. |
| Недостатки | Изменение CCM под предпочтения может затронуть другие непохожие цвета; настройка сложнее. | Малое число отсчётов 9×9×9 может создавать неестественные переходы; изменение значений влияет на интенсивность подавления шума пикселя и вносит шум. |

<!-- Source EN PDF p.76, block 633 -->

Выбор в проекте определяется компромиссом между цветовыми предпочтениями, переходами и шумом.

<!-- Source EN PDF p.76, block 634 -->
