## 2.3 Оценка модели

### 2.3.1 Инференс модели

После преобразования исходной модели в RKNN можно выполнить инференс в симуляторе или на плате и проверить результаты после постобработки. Если они неверны, выполните анализ точности квантованной модели и проверьте предобработку и постобработку. Основные параметры интерфейсов инференса описаны ниже.

Интерфейс инициализации rknn.init_runtime() принимает следующие параметры:

target: целевая аппаратная платформа. По умолчанию None — используется симулятор. Для получения реальных результатов на плате задайте соответствующую платформу: RK3562 / RK3566 / RK3568 / RK3588 / RK3576 / RV1103 / RV1103B / RV1106 / RV1106B / RV1126B.

device_id: идентификатор устройства, по умолчанию None. Если задан target, выбирается единственное подключённое устройство. При нескольких подключённых устройствах нужно указать нужный идентификатор. Для сетевого подключения через ADB сначала вручную выполните adb connect [IP], затем укажите идентификатор, обычно [IP] или [IP:Port]. Команда adb devices показывает все подключённые устройства.

perf_debug: включает отладочный режим оценки производительности; по умолчанию False. Исходный текст указывает вызов rknn.val_perf(), возвращающий общее время модели. При True можно получить время каждого слоя; на RV1103, RV1103B, RV1106 и RV1106B это не поддерживается.

eval_mem: включает режим оценки памяти; по умолчанию False. После установки True можно вызвать rknn.eval_memory(), чтобы получить потребление памяти моделью во время выполнения.

Интерфейс rknn.inference() принимает следующие параметры:

inputs: список входов для инференса в формате ndarray.

data_format: список форматов размещения входных данных; действует только для четырёхмерных входов. Допустимы NCHW и NHWC. По умолчанию None: все входы имеют формат NHWC.

Пример кода:

```text
ret = rknn.init_runtime(target=platform, device_id='515e9b401c060c0b')

# Preprocess
image_src = cv2.imread(IMG_PATH)
img = preprocess(image_src)

# Inference
outputs = rknn.inference(inputs=[img])

# Postprocess
outputs = postprocess(outputs)
```

Примечания: 1. Если на RV1103 / RV1106 возникает ошибка "E RKNN: failed to allocate fd, ret: -1, errno: 12", перед инференсом на подключённой плате можно выполнить в её терминале RkLunch-stop.sh, чтобы закрыть другие приложения, потребляющие память. Обновление rknn_server до 2.1.0 также может уменьшить эту проблему.

2. В версии ARM64 для rknn.init_runtime() параметр device_id не требуется.

### 2.3.2 Анализ точности модели

При проблемах с результатами инференса квантованной модели используйте rknn.accuracy_analysis() для анализа точности каждого слоя операторов.

Интерфейс rknn.accuracy_analysis() принимает следующие параметры:

inputs: список путей к входным файлам форматов jpg, png, bmp или npy.

output_dir: каталог сохранения результатов анализа; по умолчанию './snapshot'.

target: целевая аппаратная платформа. По умолчанию None — анализ выполняется в симуляторе. Если задана платформа RK3562 / RK3566 / RK3568 / RK3588 / RK3576 / RV1103 / RV1103B / RV1106 / RV1106B / RV1126B, получаются результаты каждого слоя при выполнении на ней и проводится анализ точности.

device_id: идентификатор устройства, по умолчанию None. Если задан target, выбирается единственное устройство. При нескольких устройствах задайте нужный идентификатор. Для сетевого ADB-подключения сначала выполните adb connect [IP], затем укажите идентификатор, обычно [IP] либо [IP]:[Port].

Примечания:

1. Анализ может завершиться ошибкой, если модель слишком велика и на плате недостаточно места. Проверьте свободное место командой df -h в терминале платы. При необходимости удалите ненужные файлы, чтобы раздел с output_dir вмещал файлы результатов.

2. После загрузки модели через rknn.load_rknn() анализ точности недоступен, поскольку в RKNN-модели отсутствуют сведения исходной модели.

3. В версии ARM64 rknn.accuracy_analysis() не требует device_id; эта версия не поддерживает анализ на другом устройстве, подключённом через ADB.

Пример кода:

```text
ret = rknn.accuracy_analysis(inputs=[img_path], target=platform, device_id='515e9b401c060c0b')
```

### 2.3.3 Оценка производительности модели

rknn.eval_perf() выводит текущие аппаратные частоты и результаты оценки производительности. Параметр fix_freq определяет, следует ли пытаться зафиксировать частоты CPU/NPU/DDR: True включает фиксацию, False отключает; по умолчанию True. Если при инициализации rknn.init_runtime() задан perf_debug=True, выводятся время каждого слоя и общее время. При False выводится только общее время.

Примечание:

1. RV1103 / RV1103B / RV1106 / RV1106B не поддерживают perf_debug=True и выводят только общее время модели.

Пример кода:

```text
ret = rknn.init_runtime(target=platform, perf_debug=True)
perf_detail = rknn.eval_perf()
```

Ниже для RK3588 показаны частоты, выводимые eval_perf; поддерживаемые частоты зависят от прошивки. У CPU RK3588 архитектура big.LITTLE, поэтому для CPU выводится несколько значений в KHz, а частоты NPU и DDR приведены в Hz.

```text

  - 2304000

DDR Current Frequency List:
```

### 2.3.4 Оценка использования памяти моделью

rknn.eval_memory() получает результаты оценки памяти модели. Если при инициализации rknn.init_runtime() задан eval_mem=True, выводится потребление памяти каждой частью.

Пример кода:

```text
ret = rknn.init_runtime(target=platform, eval_mem=True)
memory_detail = rknn.eval_memory()
```
