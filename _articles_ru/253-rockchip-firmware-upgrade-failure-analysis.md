# Ошибки обновления прошивки Rockchip: Boot Code, IDB, NAND и EMMC

Справочный материал для ArmSoM: полное техническое содержание RK Firmware Upgrade Failure Analysis 1.2. Единственный источник — китайский PDF на25 страницах; английский, русский и немецкий переведены полностью, все используют45 исходных рисунков. Журналы, сравнение бинарных файлов, платы и осциллограммы сохранены в оригиналах; неразборчивые символы не выдуманы. Читаемый batch-код и последняя таблица питания также переписаны текстом. Примеры относятся к старым SoC/инструментам, не испытаниям ArmSoM. Проверяйте аппаратуру, BSP, datasheet памяти и цепочку загрузки.

## Границы и вопросы источника

- Это рекомендации диагностики, не доказательство неисправности по одному сообщению. Сохраните журналы, проверьте прошивку/питание, затем исследуйте факты. Перепайка требует квалификации.
- Repair, стирание IDB, перепрошивка и запись misc разрушают данные/загрузочное состояние. Сначала резервная копия, точная цель и размер раздела. Для secure boot нужна подписанная прошивка, не обход проверки.
- Pin38-VCC, подтяжки10K и EXT CSD179/167/162 относятся лишь к подходящим компонентам/платформам. RTS_n, DATO, RK3329 отмечены как сомнительные написания; не определяйте соединения по опечатке.
- Таблицы ID исторические, не полный список. После D3 стоит разделитель без второго значения — ID не выдуман.00/FF трактуются только в контексте источника, не заменяют электрическую проверку.
- На странице25 таблица только изображением; сохранена и переписана: Ta=25°C при3.3V, VCC2.7V–3.6V, пульсации60mV peak-to-peak. Диапазоны текста100-300mA/100-700uA не равны гарантиям для показанного отдельного типа.
- Третий batch-скриншот страницы17 обрезан справа в оригинале. Команда восстановлена по предыдущему и явной замене-RK29→-RK30; изображения сохранены. Времена журналов сохранены как контекст; дата обложки, контакты и история удалены. Прошивка, стирание, регистры и аппаратные операции не выполнялись.

## 1. Обзор

На производстве и при разработке часто возникают ошибки обновления прошивки. Руководство собирает типовые проблемы и способы диагностики. Инструменты меняются, поэтому точные сообщения могут отличаться, но для одного типа ошибки обычно похожи.

Возможные причины:

1. Плохое качество сигнала USB.

2. Дефекты пайки SoC или питания.

3. Проблемы DDR.

4. Недостаточное питание.

5. Неподписанная прошивка на устройстве с secure boot.

Диагностика:

1. Проверьте пайку инструментом тестирования DDR.

2. Используйте короткий качественный кабель USB 2.0 и задний USB-порт ПК.

3. Проверьте наличие и параметры ESD-компонентов USB.

4. Измерьте напряжение и пульсации питания USB.

5. Проверьте параллельную прокладку USB и других трасс на соседних слоях.

6. Проверьте номиналы резисторов и конденсаторов SoC/USB.

7. Используйте предусмотренный платой внешний источник или батарею.

8. Устройствам secure boot нужна соответствующая правильно подписанная прошивка.

### 2.3. Подготовка IDB: пайка NAND FLASH или EMMC

Производственный инструмент сообщает об ошибке подготовки IDB:

![Исходный снимок или диаграмма, страница PDF 6, рисунок 9](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p006-figure-01.png)

Журнал производственного инструмента:

![Исходный снимок или диаграмма, страница PDF 6, рисунок 10](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p006-figure-02.png)

Инструмент разработки сообщает об ошибке записи ID_BLOCK:

![Исходный снимок или диаграмма, страница PDF 7, рисунок 11](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p007-figure-01.png)

Журнал сообщает, что NAND FLASH не найдена и запись ID_BLOCK не удалась.

Возможные причины:

1. Плохая пайка NAND FLASH/EMMC.

2. Неподдерживаемая NAND FLASH.

3. Дефекты платы.

4. Неверное питание FLASH VCCQ.

5. Неверный FLASH SEL на стороне AP.

6. Отсутствуют подтяжки CMD и D0 EMMC.

Диагностика:

1. Проверьте плату и восстановите пайку NAND FLASH/EMMC квалифицированным способом.

2. Сверьте схему и datasheet NAND, особенно вывод 38. По источнику, большинству Toshiba, Sandisk и Samsung там нужен VCC, другим — нет. Это историческое обобщение: определяющими являются datasheet и корпус конкретного компонента.

3. Для неподдерживаемой NAND получите соответствующее обновление драйвера через поддержку изготовителя и проверьте список поддерживаемых компонентов.

4. UART-журнал помогает проверить пайку. Исправная NAND выводит FLASH ID, как ниже. В описанном пути загрузки EMMC обычно не выводит FLASH ID.

![Исходный снимок или диаграмма, страница PDF 8, рисунок 12](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p008-figure-01.png)

Первый байт FLASH ID определяет изготовителя:

| ID | Изготовитель |
| --- | --- |
| 2C | Micron |
| AD | Hynix |
| 45 | Sandisk |
| 89 | Intel |
| EC | Samsung |
| 98 | Toshiba |
| 00 | NAND FLASH не подключена |
| FF | NAND FLASH не подключена |
| Другие значения | Плохая пайка или неподдерживаемая NAND FLASH. |

Второй байт обозначает ёмкость; типовые значения источника:

| ID | Ёмкость |
| --- | --- |
| 75 | 32MB |
| 76 | 64MB |
| 78、79、F1、D1 | 128MB |
| DA、71 | 256MB |
| DC | 512MB |
| D3、 | 1GB |
| D5、48 | 2GB |
| D7、68 | 4GB |
| D9、88、DE、3A、64 | 8GB |
| 3C、A8、84 | 16GB |
| Другие значения | Плохая пайка или неподдерживаемая NAND FLASH. |

Примеры диагностики:

1. Следующий журнал источник связывает с плохой пайкой NAND FLASH или EMMC.

![Исходный снимок или диаграмма, страница PDF 9, рисунок 13](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p009-figure-01.png)

2. Установлены две NAND, но система видит четыре. Источник указывает на плохую пайку CS.

![Исходный снимок или диаграмма, страница PDF 10, рисунок 14](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p010-figure-01.png)

3. Две NAND установлены и найдены, но ID неверны: первый байт 2c — Micron, второй 8C вместо ожидаемого здесь 88. Источник делает вывод о пайке. Не считайте любой отсутствующий в таблице ID неисправным без datasheet.

![Исходный снимок или диаграмма, страница PDF 10, рисунок 15](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p010-figure-02.png)

### 2.6. Ошибка проверки чипа

Проверка чипа обычно не проходит, когда прошивка не соответствует SoC. При разработке возможен неверный параметр упаковки. По источнику, инструмент разработки не проверяет чип: неверная прошивка не загрузится либо вернётся в режим обновления. Нужна корректная прошивка.

![Исходный снимок или диаграмма, страница PDF 17, рисунок 33](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p017-figure-01.png)

Пример для RK30 ошибочно упакован как RK29. Откройте `mkupdate.bat` и исправьте параметр чипа.

![Исходный снимок или диаграмма, страница PDF 17, рисунок 34](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p017-figure-02.png)

```bat
Afptool -pack ./ Image\update.img
RKImageMaker.exe -RK29 RK30xxLoader(L)_V1.20.bin Image\update.img update.img -os_type:androidos
rem update.img is new format, Image\update.img is old format, so delete older format
del Image\update.img
pause
```

В данном примере RK30 измените параметр `RKImageMaker.exe` на `-RK30`.

![Исходный снимок или диаграмма, страница PDF 17, рисунок 35](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p017-figure-03.png)

```bat
Afptool -pack ./ Image\update.img
RKImageMaker.exe -RK30 RK30xxLoader(L)_V1.20.bin Image\update.img update.img -os_type:androidos
rem update.img is new format, Image\update.img is old format, so delete older format
del Image\update.img
pause
```

Подробности — в документах каталога инструмента создания прошивки.

## 3. Другие проблемы

### 3.1. После перезагрузки остаётся режим обновления

Случай 1: после инструмента разработки устройство не запускается, по USB видно обновление. Ниже UART-журнал.

![Исходный снимок или диаграмма, страница PDF 18, рисунок 36](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p018-figure-01.png)

Читаемые ключевые состояния последовательного порта (фрагмент; полный журнал остаётся на оригинальном снимке):

```text
unsigned!
SecureBootEn = 0
Boot ver: 2012-11-13#1.20
Error: Invaid tag(0x00000000)!
Load failed!
Begin recover...
GetRemapTbl flag = 1
Error: Invaid tag(0x00000000) in backup!
Start RockUsb...
2900305 UsbConnected
```

Источник объясняет это записью misc.img без recovery.img.

![Исходный снимок или диаграмма, страница PDF 19, рисунок 37](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p019-figure-01.png)

Решение: повторно запишите recovery.img. Источник также описывает запись файла больше 32KB в misc для удаления команд; это разрушительная операция, неприменимая вслепую к новым разметкам.

Случай 2: источник называет RK3329 и RK3368, где без trust.img возможен отказ запуска. Запишите соответствующий trust.img. RK3329 сохранено как в источнике и требует проверки платформы.

### 3.2. EMMC не загружается при включении

Источник связывает это прежде всего с RK3188, PX3, PX2, RK3066, RK3168 после обновления loader или установки заранее прошитой памяти. Проверки:

1. Проверьте схему/разводку. CMD и DATA0-DATA7 требуют подтяжек; источник рекомендует 10K. Проверьте пайку. Не проводите сигналы EMMC через NC-выводы.

2. Измерьте осциллографом включение. CMD должен подниматься одновременно с VCCQ EMMC. При более позднем CMD часть EMMC не загружается.

![Исходный снимок или диаграмма, страница PDF 20, рисунок 38](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p020-figure-01.png)

3. Проверьте выбросы CMD/CLK. Они мешают запуску части EMMC. Источник наблюдал это у RK3066 с PMU TI и предлагает изменить последовательность питания.

![Исходный снимок или диаграмма, страница PDF 20, рисунок 39](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p020-figure-02.png)

4. Проверьте выбросы CMD, CLK, DATA; возможно последовательное согласование. Сильный звон CLK в примере может вызвать логические ошибки.

![Исходный снимок или диаграмма, страница PDF 21, рисунок 40](/docs/rockchip-firmware-upgrade-failure-analysis/assets/cn-p021-figure-01.png)

5. Проверьте пульсации VCC и подходящие фильтрующие конденсаторы.

6. Для заранее прошитой памяти проверьте EXT CSD.

EXT CSD источника: байт179 = 0x08 (boot1 без ACK); байт167 = 0x1F; байт162 = 0x01 (reset pin). Остальные значения — по умолчанию. Это настройки конкретной платформы, не универсальная инструкция; некоторые изменения могут быть необратимы.

Для RK312X, RK3228, RK3366, RK3288, RK3399 остановку в MASKROM после прошивки источник обычно связывает с неверным соединением отдельных D0-D7 EMMC.

### 3.3. EMMC не загружается после сброса

Проверьте соединение EMMC_PWEN SoC с выводом EMMC, названным в источнике RTS_n. Сверьте настоящее имя по схеме/datasheet; возможная опечатка не должна определять соединение.

Для предварительной прошивки RK3188, PX3, PX2, RK3066, RK3168 источник требует EXTCSD162 = 0x01.

### 3.4. Задержка до LOADER на EMMC

Источник объясняет задержку входом BOOTROM в поиск NAND на несколько секунд. Проверки:

1. Проверьте схему/разводку, подтяжки CMD и DATA0-DATA7 (рекомендовано10K), пайку. Не используйте NC для трассировки EMMC. В примере DATA6 проходит через NC, что замедляет запуск.

### 3.5. Ошибки чтения/записи EMMC в Android

Возможные причины:

1. Недостаточное VCC/VCCQ с провалом напряжения при работе.

2. Плохая разводка и сильные помехи.

Меры устранения:

1. Проверьте влияние внешней активности, например Wi-Fi, на питание EMMC; источник рекомендует отдельное питание.
2. Измерьте bus timing осциллографом. В примере недостаточный hold time на спаде CLK в режиме DDR может вызвать логическую ошибку.
