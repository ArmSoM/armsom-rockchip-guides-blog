# Тестирование и оптимизация энергопотребления Rockchip Linux

Справочный материал для ArmSoM. Источник RK-SM-YF-385 V1.0.1 описывает измерение энергопотребления, первоначальную диагностику и оптимизацию RK3399 с Buildroot / Debian 9 для согласования производительности, энергопотребления и безопасности. Версия ядра, точная версия SDK/BSP и проверенная плата ArmSoM не указаны. Перед применением проверьте схему платы, питание, дисплей, драйверы и SDK. Ниже приведены примеры измерений изготовителя, а не испытания ArmSoM; аппаратная проверка не выполнялась.

Доступен только китайский оригинал. Английский, русский и немецкий тексты являются полными переводами; все три изображения взяты из китайского оригинала. Английских оригиналов изображений нет. Две растровые таблицы также восстановлены в редактируемом виде. Поддержка по источнику:

| Микросхема | Buildroot | Debian 9 |
| --- | --- | --- |
| RK3399 | Y | Y |

## 1. Энергопотребление в различных сценариях

Условия испытаний RK3399: CPU 4xA53+2xA72, до 1.8GHz; DDR до 856MHz; GPU до 800MHz. Далее рассматриваются неподвижный рабочий стол, воспроизведение видео, нагрузочное тестирование и глубокий сон в Buildroot / Debian 9 Linux.

## 2. Оптимизация энергопотребления системы

### 2.1 Первоначальная диагностика

#### 2.1.1 Сравнение общей мощности

Сначала сравните общую мощность в одинаковом сценарии с данными предыдущей главы. Если плата заказчика существенно отличается от эталонной платы Rockchip SDK, разложите потребление по цепям. Кроме аппаратных различий условия должны совпадать: например, используйте один и тот же файл 1080P/4K и отключите экран eDP и дисплей HDMI.

#### 2.1.2 Разложение по цепям питания

Изучите дерево питания проекта. На рисунке показана плата RK3399 Excavator. Постройте дерево по схеме, включите резистор последовательно в нужную цепь (источник обычно рекомендует 20mR) и измерьте ток. Выделены VCC3V3_SYS, VDD_CPU_B, VDD_CPU_L, VDD_GPU, VDD_LOG, VDD_0V9, VDD_CENTER, VCC_DDR и VCC_1V8. Сначала сравните потребление больших и малых ядер CPU, GPU, DDR и работу изменения частоты. При повышении напряжения проверьте кратность приращения 12.5mv. Если политика изменения частоты нормальна, исследуйте остальные периферийные устройства.

![Дерево питания RK3399 Excavator (китайский источник)](/docs/rockchip-linux-power-load-test/assets/cn-p5-1.png)

Дерево питания RK3399 Excavator (китайский источник)

#### 2.1.3 Проверка тактирования

Проверьте частоту, enable_count, prepare_count и связи родительских/дочерних тактов подсистем. Пример saradc сохраняет исходные комментарии:

```text
# 获取总的Clock状态：
cat /sys/kernel/debug//clk/clk_summary
# 设置频率（单位 HZ）：
echo 24000000 > /sys/kernel/debug/clk_saradc/clk_rate
# 获取频率：
cat /sys/kernel/debug/clk_saradc/clk_rate
# 打开 clock：
echo 1 > /sys/kernel/debug/clk_saradc/clk_enable_count
# 关闭 clock：
echo 0 > /sys/kernel/debug/clk_saradc/clk_enable_count
```

enable_count увеличивается на 1 при явном включении такта драйвером через clk_enable. Для некоторых постоянно включённых тактов значение 1 или 0 допустимо и не является главным предметом проверки. У неиспользуемых устройств проверьте CLK enable_cnt=0; иначе источник предлагает вручную отключить такт для диагностики. Сначала убедитесь, что работающие устройства не пострадают.

#### 2.1.4 Проверка доменов питания (PD)

Проверьте состояние каждого PD. Неиспользуемые модули должны быть suspend; PD отключается после приостановки всех его устройств. Исходный вывод объединён через границу страниц:

```text
# cat /sys/kernel/debug/pm_genpd/pm_genpd_summary
domain status slaves
/device runtime status
----------------------------------------------------------------------
pd_vopl on
/devices/platform/ff8f3f00.iommu active
/devices/platform/ff8f0000.vop active
pd_vopb off
/devices/platform/ff903f00.iommu suspended
/devices/platform/ff900000.vop suspended
pd_vo on pd_vopb, pd_vopl
pd_tcpc1 on
/devices/platform/ff800000.phy active
pd_tcpc0 on
/devices/platform/ff7c0000.phy active
pd_isp1 on
/devices/platform/ff924000.iommu active
/devices/platform/ff920000.rkisp1 suspended
pd_isp0 on
/devices/platform/ff914000.iommu active
/devices/platform/ff910000.rkisp1 suspended
pd_hdcp on
/devices/platform/ff940000.hdmi active
```

Конфигурация DTS на примере vopb:

```text
vopb: vop@ff900000 {
    power-domains = <&power RK3399_PD_VOPB>;
};
```

Если узел DTS не ссылается на PD, подсистема считает домен неиспользуемым и выключает после загрузки. Если ссылка есть, но у драйвера vop нет runtime-операций, устройство получает состояние unsupported, а PD остаётся включённым. При наличии ссылки и runtime-операций включением управляет драйвер. Для снижения потребления проверяйте PD summary и дерево тактов, отключая PD/CLK неиспользуемых модулей во избежание утечки внутренних MOS-транзисторов.

### 2.2 Первоначальная оптимизация

#### 2.2.1 Изменение яркости подсветки

```text
[root@rk3399:/]# cat /sys/class/backlight/backlight/brightness
200
```

Исходный диапазон 0–255; большее значение означает большую яркость. Сначала установите 100, затем при необходимости снижайте дальше.

```text
echo 100 > /sys/class/backlight/backlight/brightness
```

#### 2.2.2 Снижение частоты обновления

Если в данном сценарии частота кадров GPU ниже 30fps, можно изменить частоту обновления DSI. Ниже исходный частичный diff: окончание узла в источнике отсутствует, поэтому это не самостоятельный полный DTS.

```text
native-mode= <&mipi_1280x800>;
mipi_1280x800: mipi-1280x800 {
-clock-frequency = <76000000>;
+ clock-frequency = <60000000>;//45fps
hactive = <800>;
vactive = <1280>;
hsync-len = <10>;
```

#### 2.2.3 Отключение ISP

Отключите неиспользуемые модули в DTS. Для USB-камеры источник предлагает отключить ISP:

```text
+&isp0{
+    status = "disabled";
+};
+
+&isp1 {
+    status = "disabled";
+};
+
+&isp0_mmu {
+    status = "disabled";
+};
+
+&isp1_mmu {
+    status = "disabled";
+};
```

#### 2.2.5 Настройка target load

По умолчанию load равен 90. Перенос строки PDF внутри одной команды cat устранён:

```text
[root@rk3399:/sys/devices/system/cpu/cpufreq/policy4/interactive]# cat target_loads
90
```

Источник предлагает следующие значения. Пример всё ещё показывает вывод cat и не содержит команды записи; cat не выполняет настройку:

```text
[root@rk3399:/sys/devices/system/cpu/cpufreq/policy4/interactive]# cat target_loads
65 1008000:70 1200000:75 1416000:80 1608000:90
```

## Редакторские замечания и адаптация

Сохранены обозначения `20mR` и `12.5mv`: обычно это миллиомы и милливольты, но нужны проверка схемы и PMIC. Двойной слеш в `/sys/kernel/debug//clk/clk_summary` и пути `clk_saradc` сохранены; сверьте с debugfs используемого ядра. Мощность SoC, входная мощность платы и измерения без дисплея различаются; их нельзя смешивать. Округление исходного текста не заменено расчётами из таблиц. Значения температуры/напряжения в 2.2.4 не являются универсально безопасными для всех SDK.
