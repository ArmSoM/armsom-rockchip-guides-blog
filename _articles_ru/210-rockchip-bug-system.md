# Rockchip: руководство по системе обращений

Справка по процессу разработки ArmSoM на основе китайского/английского руководства Rockchip Bug System V1.1.3 (24/27 страниц). Это порядок поддержки SDK и подачи обращений, а не заявление о поддержке драйверов конкретной платы, SoC или ядра. Требуются разрешённая учётная запись, коммерческое согласование и доступ к SDK. Статья не предоставляет прав доступа; вход, изменения учётных записей, отправка обращений и аппаратные проверки не выполнялись.

Безопасность: общий пароль FTP из оригинала не публикуется; доступ запрашивается у уполномоченного представителя. Снимки письма сброса пароля приведены в обезличенных копиях: URL с токеном полностью закрыт; текстовые шаги сохранены. Остальные снимки сохраняют язык оригинала. Нетехническая глава 5 с контактами/жалобами удалена, номер главы 6 сохранён. Различающиеся ссылки Camera приведены вместе. Путь data/arn/trace.txt и конечный обратный апостроф в списке manifest Android — неразрешённые вопросы оригинала. Исторические URL сохранены для прослеживаемости, доступность не проверялась.

## 1. Руководство по работе

### 1.1 Процесс подачи заявки

Учётная запись на https://redmine.rock-chips.com создаётся системой после оформления заявки. Схема ниже показывает процесс заявки на SDK.

![Процесс заявки на SDK](/docs/rockchip-bug-system/assets/en-p005-flowchart.png)

Обычно предоставляется одна учётная запись. Для особых случаев — нескольких проектов или крупных подразделений — несколько записей допускаются после согласования.

### 1.2 Вход

После завершения коммерческого оформления система отправляет письмо о создании учётной записи.

![Интерфейс из оригинала — 6](/docs/rockchip-bug-system/assets/en-p006-figure-01.png)

В письме указаны имя входа, первоначальный пароль и связанный адрес электронной почты. Откройте сайт для входа.

### 1.3 Активация

Введите имя входа и первоначальный пароль, чтобы активировать учётную запись.

![Интерфейс из оригинала — 6](/docs/rockchip-bug-system/assets/en-p006-figure-02.png)

После активации и входа можно пользоваться системой.

### 1.4 Создание обращения

После активации создайте обращение в следующем порядке.

#### 1.4.1 Выбор проекта FAE

Выберите проект FAE в раскрывающемся списке справа вверху.

![Интерфейс из оригинала — 7](/docs/rockchip-bug-system/assets/en-p007-figure-01.png)

#### 1.4.2 Новое обращение

a. Нажмите кнопку создания нового обращения.

![Интерфейс из оригинала — 7](/docs/rockchip-bug-system/assets/en-p007-figure-02.png)

b. Прочитайте уведомление Redmine и указания, затем нажмите «确认» (подтвердить).

![Интерфейс из оригинала — 8](/docs/rockchip-bug-system/assets/en-p008-figure-01.png)

#### 1.4.3 Заполнение обращения

Подробно опишите проблему, чтобы инженеры могли понять запрос и требования.

![Интерфейс из оригинала — 9](/docs/rockchip-bug-system/assets/en-p009-figure-01.png)

### 1.5 Атрибуты обращения

Поля обращения:

- Трекер: дефект, функция, поддержка или тест — в зависимости от категории.
- Тема: модель чипа + версия SDK + краткое описание, например RK3588_Rockchip_Android13.0_SDK и описание неисправности.
- Описание: подробные шаги воспроизведения, сравнительные данные, цель, текущее состояние и предварительный анализ. Прикладывайте журналы, снимки экрана, фотографии и видео. Для файлов более 10M предоставляйте ссылку на облачное хранилище.
- Состояние: New — создано; Confirmed — назначен инженер, выполняется работа; Feedback — предложено реализуемое решение и ожидается ответ; Resolved — инженер считает проблему решённой, требуется проверка; Closed — решение проверено; Hung up — эффективное решение пока отсутствует.

- Reopen: решённая проблема возникла снова.
- Приоритет: низкий, обычный, срочный или немедленный.
- Целевая версия: версия SDK.
- Поставщик чипа RK: если неизвестен, уточните у ответственного лица.
- Тип продукта.
- Component_fae: модуль; если нужного нет, выберите others.
- Серьёзность: Fatal, Serious, Bad или Warning.
- Тип проблемы: common, special, general или simple.
- Контактное имя и телефон инженера для связи.
- Вероятность возникновения.

После подтверждения решения своевременно закрывайте обращение. Большое число нерешённых обращений без обновлений может повлиять на скорость обработки.

### 1.6 Поиск проблем

Типичные обращения собраны для поиска: https://redmine.rock-chips.com/projects/redmine-issues/issues .

### 1.7 Проверка аппаратной части

Для первого проекта или ключевого проекта, подтверждённого коммерческим подразделением, настоятельно рекомендуется однократная проверка оригиналов принципиальной схемы и PCB, если не согласовано исключение. Особые требования уточняйте через ответственного представителя. Рекомендуется не менять шаблон DDR: он уже прошёл моделирование и массовое производство. Любое изменение необходимо согласовать и при необходимости организовать моделирование.

Если конфиденциальность не позволяет отправить исходные файлы, привезите их для проверки на месте. Заранее согласуйте посещение инженеров в Шанхае, Шэньчжэне или Фучжоу.

## 2. Многопользовательская работа

### 2.1 Введение

В личных настройках доступны основные сведения, язык, адреса электронной почты и уведомления. Нажмите My account справа вверху.

![Интерфейс из оригинала — 11](/docs/rockchip-bug-system/assets/en-p011-figure-01.png)

Откроется страница My account.

![Интерфейс из оригинала — 11](/docs/rockchip-bug-system/assets/en-p011-figure-02.png)

### 2.2 Использование

#### 2.2.1 Основные сведения

В нижней части страницы укажите имя, фамилию и электронную почту.

![Интерфейс из оригинала — 12](/docs/rockchip-bug-system/assets/en-p012-figure-01.png)

Используйте наименование компании и рабочий адрес электронной почты для идентификации.

#### 2.2.2 Язык

a. Нажмите Language.

![Интерфейс из оригинала — 12](/docs/rockchip-bug-system/assets/en-p012-figure-02.png)

b. Выберите язык и сохраните настройки.

![Интерфейс из оригинала — 13](/docs/rockchip-bug-system/assets/en-p013-figure-01.png)

#### 2.2.3 Уведомления

Настройте уведомления по потребностям проекта с помощью раскрывающегося списка справа.

![Интерфейс из оригинала — 14](/docs/rockchip-bug-system/assets/en-p014-figure-01.png)

Доступны шесть вариантов: все события моих проектов; все события выбранных проектов; наблюдаемые события или события с моим участием; наблюдаемые или назначенные мне; наблюдаемые или созданные мной; не уведомлять.

![Интерфейс из оригинала — 15](/docs/rockchip-bug-system/assets/en-p015-figure-01.png)

c. Можно отключить уведомления об изменениях, внесённых вами самостоятельно.

![Интерфейс из оригинала — 15](/docs/rockchip-bug-system/assets/en-p015-figure-02.png)

#### 2.2.4 Несколько пользователей

При совместном использовании учётной записи несколько адресов могут получать обновления. Нажмите Emails справа вверху.

![Интерфейс из оригинала — 16](/docs/rockchip-bug-system/assets/en-p016-figure-01.png)

b. Введите дополнительный адрес и нажмите Add.

![Интерфейс из оригинала — 16](/docs/rockchip-bug-system/assets/en-p016-figure-02.png)

c. Основной и дополнительные адреса получают изменения состояния обращений.

![Интерфейс из оригинала — 17](/docs/rockchip-bug-system/assets/en-p017-figure-01.png)

d. На основной адрес из §2.2.1 придёт уведомление.

![Интерфейс из оригинала — 17](/docs/rockchip-bug-system/assets/en-p017-figure-02.png)

e. Удаляйте адреса ушедших сотрудников, чтобы не занимать список рассылки и не раскрывать конфиденциальные сведения.

![Интерфейс из оригинала — 18](/docs/rockchip-bug-system/assets/en-p018-figure-01.png)

f. Об удалении сообщается на основной адрес.

![Интерфейс из оригинала — 18](/docs/rockchip-bug-system/assets/en-p018-figure-02.png)

#### 2.2.5 Смена пароля

a. Справа нажмите Change password.

![Интерфейс из оригинала — 18](/docs/rockchip-bug-system/assets/en-p018-figure-03.png)

b. Введите текущий и новый пароль, затем примените изменение.

![Интерфейс из оригинала — 19](/docs/rockchip-bug-system/assets/en-p019-figure-01.png)

c. Система отправляет уведомление о смене пароля.

![Интерфейс из оригинала — 19](/docs/rockchip-bug-system/assets/en-p019-figure-02.png)

#### 2.2.6 Забытый пароль

Используйте основной адрес электронной почты для восстановления. Откройте https://redmine.rock-chips.com/login и нажмите Lost password.

![Интерфейс из оригинала — 20](/docs/rockchip-bug-system/assets/en-p020-figure-01.png)

b. Введите электронную почту и отправьте запрос.

![Интерфейс из оригинала — 20](/docs/rockchip-bug-system/assets/en-p020-figure-02.png)

d. Письмо содержит ссылку для сброса и имя входа. Ниже приведена обезличенная копия: вся ссылка с токеном закрыта. Используйте только собственное разрешённое письмо.

![Интерфейс из оригинала — 21](/docs/rockchip-bug-system/assets/en-p021-figure-02.png)

## 3. Материалы

Материалы распространяются через Redmine и FTP. Раздел документов https://redmine.rockchip.com.cn/projects/fae/documents содержит технические изменения и перечни ключевых компонентов Flash, DDR, eMMC, WiFi и Camera.

### 3.1 FTP

FTP: ftp://www.rockchip.com.cn . Доступ запрашивайте у уполномоченного представителя; общий пароль из оригинала удалён из публичной версии.

- 01-Wifi, 02-BT и 11-Linux: драйверы беспроводных устройств, инструменты сертификации и поддержка.
- 05-patch: многооконность, цветовая температура, несколько USB/разделов, подавление эха/шума, HDMI_IN, a2dp sink.
- 06: исходники проигрывателей, PCBA, стресс-тестов, WiFi Display и OtaUpdate.
- 08: Datasheet.
- 11-Linux: DPDK, WiFi/BT и приложения.
- 10-Security_Patch: исправления безопасности Android.
- 12-Rockchip_RKIVE_Simulator_release: документация и исправления.
- 13-Rockchip_SDK_Release_Note: версии SDK и примечания к выпускам.

## 4. Поддержка на месте

Rockchip распределяет инженеров по проектам и проблемам; предусмотрены два варианта.

### 4.1 В офисе Rockchip

Подходит для проверки проекта, лабораторных измерений, специальных программно-аппаратных задач, воспроизведения проблем, которые нельзя решить через систему обращений, работы со специальным оборудованием, ускорения текущего проекта и срочных ключевых задач. Запишитесь минимум за один рабочий день через ответственного представителя. Rockchip согласует площадку в Шанхае, Шэньчжэне или Фучжоу.

### 4.2 У заказчика

Проверка проекта и лабораторные испытания.

Особые задачи ПО/аппаратуры, производственная линия, среда воспроизведения, специальное оборудование, медленная обработка обращений или срочные ключевые вопросы могут потребовать выезда. Запросите его минимум за два рабочих дня; после коммерческого согласования Rockchip назначает инженеров. Из-за ограниченного числа сотрудников предпочтительно посещение заказчиком Rockchip.

## 6. Вопросы и ответы

### 6.1 Пример программной проблемы

Пример показывает, как сократить затраты на обмен сведениями.

#### 6.1.1 Необходимые сведения

a. Журналы logcat и ядра.

Через последовательную консоль или adb shell выполните `logcat -v time`. При избытке сообщений перед запуском APK очистите журнал командой `logcat -c`, затем включите `logcat -v time` и запустите APK. Журнал ядра получите через последовательную консоль или `dmesg`. Для зависания или принудительного закрытия оригинал указывает `data/arn/trace.txt`; написание arn сохранено, путь необходимо проверить в используемом Android.

b. Подробные шаги воспроизведения.

c. Версия SDK, пример RK3588 Linux:
