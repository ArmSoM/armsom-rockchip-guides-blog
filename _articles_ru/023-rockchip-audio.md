# ArmSoM Rockchip Audio: полное руководство по драйверам, настройке и отладке

<style>.article-content img{aspect-ratio:auto;width:auto;max-width:100%;margin:24px auto}.article-content table{font-size:14px}.article-content th{min-width:90px}</style>

Руководство предназначено для разработки аудио на платформах ArmSoM Rockchip, включая Sige7 / AIM7 (RK3588) и Sige5 / CM5 / AIM5 (RK3576). Выбирайте разделы по SoC, кодеку на плате или плате-носителе, схеме соединений и SDK/BSP. Возможность контроллера не означает, что интерфейс выведен на каждой плате. Оригинал охватывает Linux 4.4, 4.19, 5.10 и 6.1; сверяйте драйверы и свойства Device Tree с BSP. Измерения и примеры принадлежат Rockchip и не являются тестами ArmSoM.

Источник: Rockchip_Developer_Guide_Audio_EN.pdf, V2.4.0. Технические главы сохранены; служебные заявления, аудитория и история изменений исключены. Исправления и вопросы перечислены в [редакционных замечаниях](/docs/rockchip-audio/EDITORIAL-NOTES.md).

##### 1.2.2.3 Задержка

<!-- source-page: 14; block: en-0053 -->

Общая задержка = фазовая задержка + задержка FIFO.

<!-- source-page: 14; block: en-0054 -->

###### 1.2.2.3.1 Фазовая задержка

<!-- source-page: 14; block: en-0055 -->

RATIO = выходная частота дискретизации / входная частота дискретизации.

<!-- source-page: 14; block: en-0056 -->

| RATIO | Фазовая задержка |
| --- | --- |
| RATIO &lt;= 1 | 32 отсчётов при SR(input) |
| RATIO &gt; 1 | 32 * RATIO отсчётов при SR(input) |

<!-- source-page: 14; block: en-0057 -->

###### 1.2.2.3.2 Задержка FIFO

<!-- source-page: 14; block: en-0058 -->

Задержка FIFO = ASRC_IN_THRESH + ASRC_OUT_THRESH.

<!-- source-page: 14; block: en-0059 -->

Параметр настраивается. Текущая программная конфигурация приведена в таблице:

<!-- source-page: 14; block: en-0060 -->

| Порог | Значение |
| --- | --- |
| ASRC_IN_THRESH | 2 |
| ASRC_OUT_THRESH | 24 |

<!-- source-page: 15; block: en-0061 -->

###### 1.2.2.3.3 Пример

<!-- source-page: 15; block: en-0062 -->

| Пример | Задержка |
| --- | --- |
| 48k -&gt; 16k | Задержка = 32 + 2 + 24 = 58 отсчётов при 48k, 1.2ms |
| 48k -&gt; 48k | Задержка = 32 + 2 + 24 = 58 отсчётов при 48k, 1.2ms |
| 48k -&gt; 96k | Задержка = 32 * (96 / 48) + 2 + 24 = 90 отсчётов при 48k, 1.9ms |

<!-- source-page: 15; block: en-0063 -->

Примечание: для уменьшения задержки настройте задержку FIFO.

#### 1.2.3 I2S

<!-- source-page: 15; block: en-0067 -->

В платформе RK используются два типа контроллеров: I2S и I2S-TDM. Первый поддерживает I2S и PCM, второй — I2S, PCM и TDM.

<!-- source-page: 15; block: en-0068 -->

##### 1.2.3.1 Возможности контроллера I2S

<!-- source-page: 15; block: en-0069 -->

Восьмиканальный I2S: стандартный формат, левое и правое выравнивание.

<!-- source-page: 15; block: en-0070 -->

#### 1.2.6 VAD

<!-- source-page: 19; block: en-0132 -->

VAD (Voice Activity Detection) получает данные от DAI, выполняет статистический анализ и при достижении порога вызывает прерывание для пробуждения системы. Упрощённый поток данных показан на рисунке 1-1.

<!-- source-page: 20; block: en-0133 -->

![Иллюстрация из оригинала: 1.2.6 VAD (p. 20)](/docs/rockchip-audio/assets/en-p020-fig01.png)

<!-- source-page: 20; block: en-0134 -->

Рисунок 1-1. Поток данных RK VAD

<!-- source-page: 20; block: en-0135 -->

1. Во время сна продолжается работа DAI → VAD → SRAM. VAD непрерывно принимает данные, фильтрует и адаптивно оценивает шум, сохраняет звук в кольцевом буфере SRAM.

<!-- source-page: 20; block: en-0136 -->

2. При превышении порога VAD вызывает прерывание и будит CPU. Процессор отключает VAD, после чего поток автоматически переключается на стандартный тракт записи DAI → DMAC → DDR → CPU.

<!-- source-page: 20; block: en-0137 -->

3. CPU без разрыва добавляет данные SRAM в буфер записи. Для пользовательского приложения обработка прозрачна.

<!-- source-page: 20; block: en-0138 -->

4. После пробуждения ASR-приложение анализирует запись, например обнаруживает ключевые слова.

<!-- source-page: 20; block: en-0139 -->

##### 2.3.1.9 mclkout / mclkin

<!-- source-page: 31; block: en-0260 -->

<!-- source-page: 31; block: en-0261 -->

| sai | mclk | Описание |
| --- | --- | --- |
| master | out | SoC выдаёт тактирование периферии |
| master | in | SAI использует внешний MCLKIN; типовой сценарий — единый источник аудиотактирования |
| slave | out | Периферия ведущая; MCLK предоставляет SoC |
| slave | in | Нет сценария применения |

<!-- source-page: 31; block: en-0262 -->

Пример: mclkout.

<!-- source-page: 31; block: en-0263 -->

```text
rk817_codec: codec {

        assigned-clocks = <&mclkout_sai0>;
        assigned-clock-rates = <12288000>;
        pinctrl-names = "default";
        pinctrl-0 = <&i2s0m0_mclk>;
        hp-volume = <20>;
        spk-volume = <3>;
        mic-in-differential;
        status = "okay";
};
```

<!-- source-page: 32; block: en-0265 -->

Пример: mclkin.

<!-- source-page: 32; block: en-0266 -->

```text
&sai0 {
        assigned-clocks = <&cru CLK_SAI0>;
        assigned-clock-parents = <&mclkin_i2s0>;
        pinctrl-0 = <&sai0_sdi
                     &sai0_sdo
                     &sai0_lrck
                     &sai0_sclk
                     &sai0_mclk>;
};
&mclkin_sai0 {
        clock-frequency = <24576000>;
        status = "okay";
};
```

<!-- source-page: 36; block: en-0296 -->

```text
&vad {
        rockchip,buffer-time-ms = <100>;
};
```

<!-- source-page: 46; block: en-0418 -->

Увеличение буфера повышает задержку ASR, а объём SRAM ограничен. Выбирайте размер, обеспечивающий целостность данных на интервале от пробуждения до начала обработки приложением. Если этот интервал слишком велик, оптимизируйте его.

<!-- source-page: 46; block: en-0419 -->

Подробности: kernel/Documentation/devicetree/bindings/sound/rockchip,vad.txt.

### 2.4 Разработка драйвера Combo DAI

<!-- source-page: 47; block: en-0421 -->

#### 2.4.1 Настройка дочерних DAI

<!-- source-page: 47; block: en-0422 -->

| Свойство | Значение | Описание |
| --- | --- | --- |
| dais | &lt;phandle&gt;... | Дочерние DAI объединяются в Combo DAI. Свойство rockchip,no-dmaengine отключает привязанный DMA engine дочернего DAI; регистрацию и привязку централизованно выполняет Combo DAI. |

<!-- source-page: 47; block: en-0423 -->

Пример: объединение i2s_8ch_2 и pdm_8ch в Combo DAI.

<!-- source-page: 47; block: en-0424 -->

```text
&i2s_8ch_2 {
        status = "okay";
        rockchip,no-dmaengine;
};
&pdm_8ch {
        status = "okay";
        rockchip,no-dmaengine;
};
&multi-dais {
        dais = <&i2s_8ch_2>, <&pdm_8ch>;
};
```

<!-- source-page: 47; block: en-0425 -->

#### 2.4.2 Распределение каналов

<!-- source-page: 47; block: en-0426 -->

| Свойство | Значение | Описание |
| --- | --- | --- |
| capture,channel-mapping | &lt;int ...&gt; | Число каналов записи каждого объединяемого дочернего DAI |
| playback,channel-mapping | &lt;int ...&gt; | Число каналов воспроизведения каждого объединяемого дочернего DAI |

<!-- source-page: 47; block: en-0427 -->

Пример: стереовоспроизведение и восьмиканальная запись — шесть микрофонов плюс два опорных канала.

<!-- source-page: 47; block: en-0428 -->

```text
&multi-dais {
        dais = <&i2s_8ch_2>, <&pdm_8ch>;
        playback,channel-mapping = <2 0>;
        capture,channel-mapping = <2 6>;
};
```

<!-- source-page: 48; block: en-0429 -->

#### 2.4.3 Режим ведущего/ведомого

<!-- source-page: 48; block: en-0430 -->

| Свойство | Значение | Описание |
| --- | --- | --- |
| bitclock-master | &lt;int ...&gt; | Источник битового тактирования: 1 означает ведущий режим, устройство выдаёт тактирование. |
| frame-master | &lt;int ...&gt; | Источник кадрового тактирования: 1 означает ведущий режим, устройство выдаёт тактирование. |

<!-- source-page: 48; block: en-0431 -->

Пример 1: i2s_8ch_2 и pdm_8ch образуют восьмиканальную карту записи с цифровым возвратом и массивом микрофонов. i2s_8ch_2 может быть ведущим или ведомым; здесь он ведущий. PDM поддерживает только ведущий режим.

<!-- source-page: 48; block: en-0432 -->

```text
&multi-dais {
        dais = <&i2s_8ch_2>, <&pdm_8ch>;
        capture,channel-mapping = <2 6>;
        playback,channel-mapping = <2 0>;
        bitclock-master = <1 1>;
        frame-master = <1 1>;
};
```

<!-- source-page: 48; block: en-0433 -->

Пример 2: два I2S образуют 16 каналов; один ведущий, другой ведомый. Аппаратно соедините источник тактирования с каждым ведомым DAI.

<!-- source-page: 48; block: en-0434 -->

```text
&multi-dais {
        dais = <&i2s_8ch_0>, <&i2s_8ch_1>;
        capture,channel-mapping = <8 8>;
        playback,channel-mapping = <8 8>;
        bitclock-master = <1 0>;
        frame-master = <1 0>;
};
```

<!-- source-page: 48; block: en-0435 -->

Пример 3: два I2S образуют 16 каналов, оба ведомые; тактирование предоставляет ведущий кодек.

<!-- source-page: 48; block: en-0436 -->

```text
&multi-dais {
        dais = <&i2s_8ch_0>, <&i2s_8ch_1>;
        capture,channel-mapping = <8 8>;
        playback,channel-mapping = <8 8>;
        bitclock-master = <0 0>;
        frame-master = <0 0>;
};
```

<!-- source-page: 49; block: en-0437 -->

<!-- source-page: 49; block: en-0438 -->

| Свойство | Значение | Описание |
| --- | --- | --- |

##### 2.6.1.6 Пример добавления звуковой карты

<!-- source-page: 53; block: en-0478 -->

1. Перенесите или напишите драйвер кодека.

<!-- source-page: 53; block: en-0479 -->

```text
sound/soc/codecs/Kconfig
sound/soc/codecs/Makefile
sound/soc/codecs/tas571x.c
sound/soc/codecs/tas571x.h
```

<!-- source-page: 54; block: en-0480 -->

2. Включите параметры CONFIG.

<!-- source-page: 54; block: en-0481 -->

```text
CONFIG_SND_SIMPLE_CARD
CONFIG_SND_SOC_ROCKCHIP_I2S
CONFIG_SND_SOC_ROCKCHIP_I2S_TDM
CONFIG_SND_SOC_TAS571X
```

<!-- source-page: 54; block: en-0482 -->

3. Добавьте узел звуковой карты в DTS.

<!-- source-page: 54; block: en-0483 -->

Включите I2S-узел согласно аппаратному подключению.

<!-- source-page: 54; block: en-0484 -->

```text
&i2s_8ch_1 {
        status = "okay";
        #sound-dai-cells = <0>;
        pinctrl-names = "default";
        pinctrl-0 = <&i2s_8ch_1_m0_sclktx
                     &i2s_8ch_1_m0_lrcktx
                     &i2s_8ch_1_m0_sdo0
                     &i2s_8ch_1_m0_mclk>;
};
```

<!-- source-page: 54; block: en-0485 -->

Добавьте узел кодека на соответствующую шину I2C или SPI.

<!-- source-page: 54; block: en-0486 -->

```text
&i2c1 {
        clock-frequency = <400000>;
        status = "okay";
        tas5731: tas5731@1a {
                #sound-dai-cells = <0>;
                compatible = "ti,tas5731";
                reg = <0x1a>;
                clocks = <&cru SCLK_I2S1_8CH_TX_OUT>;
                clock-names = "mclk";
                pinctrl-names = "default";
                pinctrl-0 = <&i2s_8ch_1_m0_mclk>;
                pdn-gpios = <&gpio0 RK_PA5 GPIO_ACTIVE_LOW>;
                reset-gpios = <&gpio1 RK_PA1 GPIO_ACTIVE_LOW>;
        };
};
```

<!-- source-page: 54; block: en-0487 -->

Добавьте и включите узел звуковой карты.

<!-- source-page: 55; block: en-0488 -->

```text
tas5731_sound: tas5731-sound {
        status = "okay";
        compatible = "simple-audio-card";
        simple-audio-card,format = "i2s";
        simple-audio-card,name = "rockchip,tas5731";
        simple-audio-card,mclk-fs = <256>;
        simple-audio-card,cpu {
                sound-dai = <&i2s_8ch_1>;
        };
        simple-audio-card,codec {
                sound-dai = <&tas5731>;
        };
};
```

<!-- source-page: 55; block: en-0489 -->

Убедитесь, что карта успешно создана.

<!-- source-page: 55; block: en-0490 -->

```text
# cat /proc/asound/cards
 0 [rockchiptas5731]: rockchip_tas5731 - rockchip,tas5731
```

<!-- source-page: 55; block: en-0491 -->

Примечание:

<!-- source-page: 55; block: en-0492 -->

Для MCLK действует правило «кто использует, тот запрашивает». Если кодеку нужен внешний MCLK, его драйвер должен запрашивать и управлять этим тактированием. В примере источником служит SCLK_I2S1_8CH_TX_OUT RK3308.

### 2.7 Компенсация аудиотактирования

<!-- source-page: 60; block: en-0540 -->

Точная подстройка аудиотактирования RK устраняет рассогласование систем с разными источниками частоты — UAC, HDMI IN, Bluetooth voice и других. Диапазон подстройки: ±1000 ppm, то есть миллионных долей.

<!-- source-page: 60; block: en-0541 -->

1. Включите параметры CONFIG.

<!-- source-page: 60; block: en-0542 -->

```text
CONFIG_ROCKCHIP_CLK_COMPENSATION
```

<!-- source-page: 60; block: en-0543 -->

2. Добавьте частоту дробного режима PLL. Подстройка работает только в дробном режиме; частота PLL должна быть чётным кратным MCLK. Далее рассмотрены два типа платформ.

<!-- source-page: 61; block: en-0544 -->

При отдельном аудио-PLL достаточно соблюсти условие чётной кратности. Например, RK3308: VPLL0 = 1179648000 Гц, VPLL1 = 903168000 Гц.

<!-- source-page: 61; block: en-0545 -->

Если PLL общий для аудио и других блоков, оцените влияние подстройки на эти блоки:

<!-- source-page: 61; block: en-0546 -->

a. Допустимо ли изменение ±1000 ppm? Ethernet требует точного тактирования, тогда как видеокодер не предъявляет такого же требования.

<!-- source-page: 61; block: en-0547 -->

b. Если условие a выполнено, выберите подходящую дробную частоту. Например, RV1126 одновременно требует частоту видеокодера около 500 МГц и поддержку аудио 48 кГц. Подходит 491520000 Гц, то есть 491,52 МГц; единица «MHz» в английском оригинале здесь ошибочна.

<!-- source-page: 61; block: en-0548 -->

Пример: перевод CPLL RV1126 на дробную частоту.

<!-- source-page: 61; block: en-0549 -->


<!-- source-page: 61; block: en-0550 -->

### 2.9 Динамические каналы DMA

## 3. Отладка

<!-- source-page: 65; block: en-0579 -->

Основные инструменты отладки и их применение.

<!-- source-page: 65; block: en-0580 -->

### 3.1 Измерительное оборудование

<!-- source-page: 65; block: en-0581 -->

#### 3.1.1 Мультиметр

<!-- source-page: 65; block: en-0582 -->

Измерьте питание и сопоставьте напряжение с документацией микросхемы. На SoC проверьте соответствие IO-домена программной конфигурации; на кодеке — питание каждого тракта.

<!-- source-page: 65; block: en-0583 -->

Пример: на RV1126 EVB RK817 подключён к I2S0 и работает при 1,8 В. Мультиметр подтверждает 1,8 В, как показано на схеме питания ниже.

<!-- source-page: 66; block: en-0584 -->

![Иллюстрация из оригинала: 3.1.1 Мультиметр (p. 66)](/docs/rockchip-audio/assets/en-p066-fig01.png)

<!-- source-page: 66; block: en-0585 -->

Рисунок 3-1. Питание I2S IO

<!-- source-page: 66; block: en-0586 -->

Соответствующий домен в DTS задаётся как 1,8 В:

<!-- source-page: 66; block: en-0587 -->

```text
&pmu_io_domains {
        status = "okay";
        ...
        vccio7-supply = <&vcc_1v8>;
};
```

<!-- source-page: 66; block: en-0588 -->

Предупреждение: несоответствие аппаратного питания и программной настройки может вызвать сбои или повредить микросхему.

<!-- source-page: 66; block: en-0589 -->

#### 3.1.2 Осциллограф

<!-- source-page: 66; block: en-0590 -->

Проверьте частоту, амплитуду, коэффициент заполнения и джиттер тактовых сигналов по спецификации протокола. Например, при питании 3,3 В амплитуда лишь 2 В может указывать на нагрузку внешнего устройства, замыкание на землю или неверную настройку напряжения. Захватите тактирование и данные, проверьте известный шаблон; для этого подходит и логический анализатор. Триггерный режим помогает поймать сбой — например, джиттер или выброс CLK в момент выпадения звука.

<!-- source-page: 66; block: en-0591 -->

#### 3.1.3 Генератор сигналов

<!-- source-page: 66; block: en-0592 -->

Генератор создаёт прямоугольные, треугольные и синусоидальные сигналы. Для проверки АЦП подайте известный сигнал, например синусоиду, и сравните записанный результат с исходным, оценивая искажения и точность.

<!-- source-page: 67; block: en-0593 -->

#### 3.1.4 Анализатор AP

<!-- source-page: 67; block: en-0594 -->

Аудиоанализатор проверяет характеристики АЦП/ЦАП кодека: цифровые интерфейсы, отношение сигнал/шум, гармонические искажения, динамический диапазон и другие параметры. Измерения помогают локализовать ограничения и улучшить аудиотракт.

<!-- source-page: 67; block: en-0595 -->

### 3.2 Команды отладки

<!-- source-page: 67; block: en-0596 -->

<!-- source-page: 67; block: en-0597 -->

<!-- source-page: 67; block: en-0598 -->

Примечание:

<!-- source-page: 78; block: en-0676 -->

Если обе карты имеют один источник частоты, например общий генератор OSC, накопленного рассогласования нет. Для UAC с тактированием ПК и локальной карты с тактированием устройства ошибка неизбежно накапливается и вызывает выпадения звука. Нужна программная компенсация — добавление/удаление отсчётов — либо аппаратная подстройка аудиочастоты.

#### 3.2.6 Анализ XRUN

<!-- source-page: 80; block: en-0699 -->

XRUN означает нарушение непрерывности аудиопотока. Различают underrun — нехватку данных при воспроизведении — и overrun — переполнение при записи.

<!-- source-page: 80; block: en-0700 -->

Underrun возникает, если приложение не успело заполнить буфер воспроизведения: появляются паузы или тишина. Overrun возникает, если данные записи не прочитаны вовремя и часть поступающих отсчётов теряется.

<!-- source-page: 80; block: en-0701 -->

ALSA в ядре Linux управляет буферами аудиопотока и обнаруживает XRUN. При исчерпании или переполнении буфера состояние передаётся драйверу и приложению для обработки и восстановления. Формулировка английского оригинала об обязательной генерации отдельного прерывания при XRUN не универсальна; конкретный механизм зависит от драйвера.

<!-- source-page: 80; block: en-0702 -->

Для устойчивой работы нужны своевременная обработка с низкой задержкой и достаточной пропускной способностью, эффективная буферизация, включая предварительное заполнение и двойные буферы, а также быстрые процедуры восстановления после XRUN.

<!-- source-page: 80; block: en-0703 -->

## 4. Частые вопросы

<!-- source-page: 83; block: en-0732 -->

### 4.1 Поддержка аудиоинтерфейсов

<!-- source-page: 83; block: en-0733 -->

См. раздел возможностей Rockchip Audio и техническое описание микросхемы.

<!-- source-page: 83; block: en-0734 -->

### 4.2 Звуковая карта не регистрируется

<!-- source-page: 83; block: en-0735 -->

Проверьте, что драйвер включён в сборку, согласно примеру добавления карты.

<!-- source-page: 83; block: en-0736 -->

По kmsg определите проблемный компонент: DAI, CODEC или Machine. Например, сообщение ниже означает, что DAI не зарегистрирован.

<!-- source-page: 83; block: en-0737 -->

[ 0.584114] rk-multicodecs vad-sound: ASoC: CPU DAI (null) not registered

<!-- source-page: 83; block: en-0738 -->

Если проблема в DAI, проверьте наличие DMA-каналов. При их нехватке отключите другие использующие DMA модули и повторите проверку.

<!-- source-page: 83; block: en-0739 -->

Если проблема в CODEC, измерьте питание и тактирование мультиметром и осциллографом, проверьте обмен I2C через i2c-tools.

<!-- source-page: 83; block: en-0740 -->

### 4.3 Нет звука при воспроизведении

<!-- source-page: 83; block: en-0741 -->

Убедитесь, что исходный файл не содержит тишину.

<!-- source-page: 83; block: en-0742 -->

Воспроизведите его через aplay или tinyplay, чтобы отделить проблему приложения от проблемы ядра.

<!-- source-page: 83; block: en-0743 -->

Подождите более 10 с и проверьте, не возникает ли I/O error по тайм-ауту.

<!-- source-page: 83; block: en-0744 -->

Через amixer или tinymix проверьте включение тракта ЦАП и отсутствие mute.

<!-- source-page: 83; block: en-0745 -->

Сверьте регистры IOMUX, DAI и CODEC с руководствами SoC и кодека.

<!-- source-page: 84; block: en-0746 -->

Измерьте напряжения, тактирование и данные. Проверьте наличие цифрового потока, аналоговый сигнал у выхода кодека и уровень GPIO включения PA. Последовательно локализуйте проблемный участок.

<!-- source-page: 84; block: en-0747 -->

### 4.4 Искажения при воспроизведении

<!-- source-page: 84; block: en-0748 -->

Воспроизведите тестовый файл 1k0 через aplay или tinyplay.

<!-- source-page: 84; block: en-0749 -->

Измените громкость и проверьте зависимость искажений от уровня.

<!-- source-page: 84; block: en-0750 -->

Осциллографом проверьте ограничение амплитуды и другие искажения на выходе, стабильность тактирования кодека и источника.

<!-- source-page: 84; block: en-0751 -->

Мультиметром проверьте питание по спецификации микросхемы.

<!-- source-page: 84; block: en-0752 -->

Измените число периодов и размер DMA-буфера, сравните результат.

<!-- source-page: 84; block: en-0753 -->

Последовательно проверьте узлы, способные вносить искажения.

<!-- source-page: 84; block: en-0754 -->

### 4.5 Нет звука в записи

<!-- source-page: 84; block: en-0755 -->

Подайте на кодек сигнал генератора 1 кГц.

<!-- source-page: 84; block: en-0756 -->

Запишите через arecord или tinycap, чтобы отделить проблему приложения от ядра.

<!-- source-page: 84; block: en-0757 -->

Подождите более 10 с и проверьте I/O error по тайм-ауту.

<!-- source-page: 84; block: en-0758 -->

Через amixer или tinymix проверьте тракт АЦП и отсутствие mute.

<!-- source-page: 84; block: en-0759 -->

Сверьте регистры IOMUX, DAI и CODEC с документацией.

<!-- source-page: 84; block: en-0760 -->

Измерьте напряжения, тактирование, цифровые данные и аналоговый сигнал у входа кодека. Последовательно локализуйте неисправность.

<!-- source-page: 84; block: en-0761 -->

### 4.6 Искажения при записи

<!-- source-page: 84; block: en-0762 -->

Подайте на кодек сигнал генератора 1 кГц.

<!-- source-page: 84; block: en-0763 -->

Запишите через arecord или tinycap; воспроизведите через петлю и измерьте осциллографом либо проанализируйте на ПК.

<!-- source-page: 84; block: en-0764 -->

Изменяйте цифровое и аналоговое усиление, наблюдайте форму сигнала и сравнивайте записанные данные с тестовым источником.

<!-- source-page: 84; block: en-0765 -->

Последовательно проверьте узлы, способные вносить искажения.

<!-- source-page: 85; block: en-0766 -->

### 4.7 Слишком высокая или низкая скорость воспроизведения

<!-- source-page: 85; block: en-0767 -->

Проверьте MCLK, BCLK и LRCK через clk summary.

<!-- source-page: 85; block: en-0768 -->

Подтвердите точность частот осциллографом.

<!-- source-page: 85; block: en-0769 -->

Запишите выходной сигнал инструментом ПК и проверьте потерю или добавление данных.

<!-- source-page: 85; block: en-0770 -->

Захватите выходные данные микросхемы логическим анализатором и проверьте потерю или добавление отсчётов.

<!-- source-page: 85; block: en-0771 -->

### 4.8 Периодические выпадения звука

<!-- source-page: 85; block: en-0772 -->

Обычно возникают между системами с разными источниками тактирования: UAC, Bluetooth voice, сетевое аудио и т. п.

<!-- source-page: 85; block: en-0773 -->

Причина — накопление ошибки рассогласования частот. Помогает компенсация аудиотактирования.

<!-- source-page: 85; block: en-0774 -->

Ошибки обработки границ буфера также вызывают периодические выпадения и шум. Анализируйте их средствами XRUN profiling.

<!-- source-page: 85; block: en-0775 -->

### 4.9 Шум

<!-- source-page: 85; block: en-0776 -->

Шум имеет много причин. Основные способы поиска:

<!-- source-page: 85; block: en-0777 -->

Проверьте точность тактирования и джиттер. Например, для HDA исходное руководство указывает предел менее 0,5 нс.

<!-- source-page: 85; block: en-0778 -->

Проверьте выбросы тактового сигнала, особенно в области порогов переключения: микросхема может принять их за дополнительные фронты. Некоторые IO RK, например указанные для RV1126, имеют триггер Шмитта. Проверьте поддержку в руководстве SoC: эта функция может подавлять случайные выбросы.

<!-- source-page: 85; block: en-0779 -->

Проверьте питание и землю кодека. Проникающие по ним помехи ухудшают характеристики и повышают шумовой фон.

<!-- source-page: 85; block: en-0780 -->

Используйте дифференциальные цепи для подавления синфазных помех.

<!-- source-page: 85; block: en-0781 -->

Проверьте разводку печатной платы и локализуйте источник помех.

<!-- source-page: 85; block: en-0782 -->

### 4.10 XRUN

<!-- source-page: 85; block: en-0783 -->

Для XRUN ядра см. раздел анализа XRUN. Дополнительные проверки:

<!-- source-page: 85; block: en-0784 -->

Разделите чтение/запись и обработку звука на отдельные потоки, чтобы обмен с ядром не прерывался.

<!-- source-page: 85; block: en-0785 -->

Проблемы планирования исследуйте через systrace или ftrace.

<!-- source-page: 85; block: en-0786 -->

Блокировка накопителя может задерживать чтение. Для проверки воспроизводите источник без доступа к накопителю, например /dev/zero.

<!-- source-page: 86; block: en-0787 -->

Проверьте точность тактирования: завышенная частота ускоряет расход данных. См. разделы о скорости воспроизведения и периодических выпадениях.

<!-- source-page: 86; block: en-0788 -->

### 4.11 Ошибка I/O

<!-- source-page: 86; block: en-0789 -->

Если запись или воспроизведение не отвечает более 10 с, журнал ядра может содержать playback/capture write error (DMA or IRQ trouble?).

<!-- source-page: 86; block: en-0790 -->

Проверьте регистр FIFO COUNT контроллера DAI: не остановился ли счётчик.

<!-- source-page: 86; block: en-0791 -->

Проверьте обновление DMA-прерываний через procfs: cat /proc/interrupts &#124; grep dma.

<!-- source-page: 86; block: en-0792 -->

Проверьте регистр состояния DMA-канала по смещению 0x100: не остановлен ли канал аварийно.

<!-- source-page: 86; block: en-0793 -->

В ведомом режиме DAI внешнее тактирование должно непрерывно присутствовать в течение всего жизненного цикла DAI. Если это нельзя гарантировать динамически, оставьте источник постоянно включённым.
