# RKNN-Toolkit2 API: конфигурация, преобразование, квантование и инференс

## Применимость к ArmSoM и источник

Это справка по платформе Rockchip, не отчёт испытаний ArmSoM. Источники: RK-YH-YF-412, V2.3.2, 22 китайские и 25 английских страниц. Китайская статья следует китайскому оригиналу; английская — английскому, полностью переведённому на русский и немецкий. Технических рисунков в PDF нет: весь материал представлен редактируемым текстом, таблицами и кодом, без вымышленных английских изображений. Источник охватывает RV1103/RV1103B/RV1106/RV1106B/RV1126B, RK2118, RK3562 и серии RK3566/3568/3576/3588, но не задаёт SDK/BSP и ядро конкретной платы ArmSoM. Сверяйте NPU-драйвер, Toolkit2/Runtime/Server, систему и архитектуру хоста, Python, фреймворк и формат модели. Возможности x64 нельзя автоматически переносить на ARM64. Версии, top-5, память и вывод SDK — примеры оригинала, не тесты ArmSoM. V2.3.2 обозначает исходный срез, не новейший выпуск.

## 2 Описание API RKNN-Toolkit2

<!-- source: EN PDF p6; unit 35 -->

### 2.1 Инициализация и освобождение RKNN

<!-- source: EN PDF p6; unit 36 -->

Эта группа интерфейсов создаёт и освобождает объект RKNN. Перед использованием любых API RKNN-Toolkit2 вызовите RKNN(); после завершения задачи освободите объект методом release().

<!-- source: EN PDF p6; unit 37 -->

При создании объекта RKNN параметры verbose и verbose_file управляют подробным журналом загрузки и построения модели и других операций. verbose имеет тип bool: при True RKNN-Toolkit2 печатает подробный журнал. verbose_file — строка; если она содержит путь к файлу, журнал записывается туда, причём verbose также должен быть True.

<!-- source: EN PDF p6; unit 38 -->

Пример кода:

<!-- source: EN PDF p6; unit 39 -->

```text
# Print the detailed log information.
rknn = RKNN(verbose=True)

…

rknn.release()
```

<!-- source: EN PDF p6; unit 40 -->

### 2.2 Настройка модели

<!-- source: EN PDF p6; unit 41 -->

Перед построением модели RKNN настройте её через интерфейс config.

<!-- source: EN PDF p6; unit 42 -->

| API | config |
| --- | --- |
| Описание | Задать параметры преобразования модели. |
| Параметры | mean_values: Средние значения входа. Формат параметра — список, содержащий один или несколько вложенных списков средних значений. Для модели с несколькими входами задаётся несколько вложенных списков. Длина каждого соответствует числу каналов входа. Например, [[128,128,128]] означает вычитание 128 из значений каждого из трёх каналов одного входа.<br>По умолчанию None: все средние равны нулю. |
| Параметры | std_values: Значения нормализации входа. Формат — список с одним или несколькими вложенными списками значений нормализации. Для модели с несколькими входами используется несколько вложенных списков. Длина каждого соответствует числу каналов входа. Например, [[128,128,128]] означает, что из значений трёх каналов одного входа сначала вычитается среднее, затем результат делится на 128.<br>По умолчанию None: все значения std равны единице. |
| Параметры | quant_img_RGB2BGR: Указывает, нужно ли сначала выполнить RGB2BGR при загрузке изображения для квантования. При нескольких входах соответствующие параметры разделяются ‘,’, например [True, True, False]. По умолчанию False.<br>Этот параметр обычно применяется к моделям Caffe. При обучении большинства моделей Caffe изображения набора данных сначала преобразуются RGB2BGR; в таком случае нужно задать True.<br>Параметр действует только для изображений квантования формата jpg/png/bmp. При чтении npy он игнорируется. Поэтому, если вход модели имеет формат BGR, данные npy также должны быть в BGR.<br>Параметр применяется только при чтении изображений на этапе квантования (интерфейс build) или анализа точности квантования (accuracy_analysis) и не записывается в итоговую модель RKNN. Поэтому для модели с входом BGR необходимо обеспечить формат BGR входных данных до вызова inference инструментария или функции run C-API. |
| Параметры | quantized_dtype: Тип квантования. Поддерживаются "w8a8", "w4a16", "w8a16", "w4a8", "w16a16i" и "w16a16i_dfp". По умолчанию "w8a8".<br>- w8a8: веса и активации имеют 8-битную асимметричную точность квантования. (RK2118 не поддерживается.)<br>- w4a16: веса — 4-битное асимметричное квантование, активации — 16-битная плавающая точка. (Только RK3576/RV1126B.)<br>- w8a16: веса — 8-битное асимметричное квантование, активации — 16-битная плавающая точка. (Только RK3562.)<br>- w4a8: веса — 4-битное, активации — 8-битное асимметричное квантование. (Пока не поддерживается.)<br>- w16a16i: веса и активации — 16-битное асимметричное квантование. (Только RV1103/RV1106.)<br>- w16a16i_dfp: веса и активации — 16-битное квантование с динамической фиксированной точкой. (Только RV1103/RV1106.) |
| Параметры | quantized_algorithm: Алгоритм вычисления параметров квантования каждого слоя. Поддерживаются normal, mmse, kl_divergence и gdq. По умолчанию normal.<br>Алгоритм normal отличается быстротой. Обычно рекомендуют примерно 20-100 образцов для квантования; увеличение количества данных не обязательно повышает точность.<br>Алгоритм mmse медленнее из-за переборного итерационного метода, но обычно точнее normal. Рекомендуется примерно 20-50 образцов. Количество можно увеличить или уменьшить с учётом времени квантования.<br>Алгоритм kl_divergence требует больше времени, чем normal, но значительно меньше, чем mmse. В некоторых сценариях (при неравномерном распределении признаков) kl_divergence даёт лучший результат. Рекомендуется примерно 20-100 образцов.<br>Алгоритм gdq действует только для w4a16 и w8a16 и позволяет повысить точность весов этих типов. Рекомендуется более 200 образцов. |
| Параметры | quantized_method: Поддерживаются layer, channel и group{SIZE}. По умолчанию channel.<br>- layer: для каждого веса используется только один набор параметров квантования.<br>- channel: каждый канал весов имеет собственный набор параметров квантования. Обычно channel точнее layer.<br>- group{SIZE}: на основе channel веса каждого выходного канала дополнительно делятся по входному каналу на группы размера {SIZE}. Каждая группа имеет собственный набор параметров квантования. Обычно group{SIZE} точнее channel. {SIZE} — значение, кратное 32, от 32 до 256, например 'group32' или 'group128'. group{SIZE} действует только при quantized_dtype = w4a16. |
| Параметры | float_dtype: Тип данных с плавающей точкой без квантования. Поддерживается float16. По умолчанию float16. |
| Параметры | optimization_level: Уровень оптимизации модели. По умолчанию 3.<br>Изменение уровня позволяет отключить некоторые или все правила оптимизации при преобразовании. Значение 3 включает все оптимизации. Значение 2 или 1 отключает часть оптимизаций, способных влиять на точность некоторых моделей. Значение 0 отключает все оптимизации. |
| Параметры | target_platform: Целевая платформа чипа для модели RKNN. Поддерживаются 'rv1103', 'rv1103b', 'rv1106', 'rv1106b', 'rv1126b', 'rk2118', 'rk3562', 'rk3566', 'rk3568', 'rk3576' и 'rk3588'. По умолчанию None. |
| Параметры | custom_string: Добавить пользовательскую строку в модель RKNN для последующего запроса во время выполнения. По умолчанию None. |
| Параметры | remove_weight: Удалить веса и создать подчинённую модель RKNN, которая может совместно использовать веса полной модели RKNN, чтобы уменьшить потребление памяти. По умолчанию False. |
| Параметры | compress_weight: Сжать веса модели, чтобы уменьшить размер модели RKNN. По умолчанию False. |
| Параметры | single_core_mode: Генерировать ли только одноядерную модель; это может уменьшить размер модели RKNN и потребление памяти. По умолчанию False. Действует только для RK3588 / RK3576. По умолчанию False. |
| Параметры | model_pruning: Прореживание модели: для моделей с разреженными весами уменьшает размер и вычислительную нагрузку преобразованной модели RKNN. По умолчанию False. |
| Параметры | op_target: Задаёт цель выполнения каждой операции (NPU/CPU/GPU и т. д.). Формат: {'op0_output_name':'cpu', 'op1_output_name':'cpu', ...}; либо по op_type: {'op_type':'cpu‘, 'op0_output_name':'cpu'....}. Допускается смешение обоих способов, например {'op_type':'cpu‘, 'op0_output_name':'cpu'....}. По умолчанию None.<br>'op0_output_name' и 'op1_output_name' — имена выходных тензоров соответствующих OP, получаемые из результатов accuracy_analysis. 'cpu' и 'npu' означают выполнение соответствующего этому тензору OP на CPU или NPU. Доступны 'cpu' / 'npu' / 'gpu' / 'auto'; 'auto' автоматически выбирает цель.<br>op_type также получают из результатов accuracy_analysis. Этот способ задаёт цель для всех OP данного типа в модели, например {'Add':'cpu', 'Expand':'cpu',....}. |
| Параметры | dynamic_input: Имитирует динамический вход по нескольким наборам форм входов, заданным пользователем. Формат: [[input0_shapeA, input1_shapeA, ...], [input0_shapeB, input1_shapeB, ...], ...].<br>По умолчанию None; экспериментальная функция.<br>Например, исходная форма входа [1,3,224,224], [1,3,height,width] или [1,3,-1,-1], но развёртываемая модель должна поддерживать три формы: [1,3,224,224], [1,3,192,192] и [1,3,160,160]. Можно задать dynamic_input=[[[1,3,224,224]], [[1,3,192,192]], [[1,3,160,160]]]. После преобразования в RKNN для инференса следует передавать входные данные соответствующей формы.<br>Примечания:<br>1. Функцию можно включить только тогда, когда сама исходная модель поддерживает динамический вход, иначе возникнет ошибка.<br>2. Если исходная форма динамическая, разные значения можно задавать только для динамических осей. |
| Параметры | quantize_weight: Если 'do_quantization' в rknn.build равно False, уменьшает размер модели rknn квантованием части весов.<br>По умолчанию False. |
| Параметры | remove_reshape: Удаляет возможные 'Reshape' на входах и выходах модели для повышения производительности выполнения. По умолчанию False.<br>Примечание: включение может изменить форму входных или выходных узлов. Следите за предупреждениями при преобразовании и учитывайте изменение форм при развёртывании. |
| Параметры | sparse_infer: Разреженный инференс для уже разреженных моделей с целью повышения производительности. Только RK3576/RV1126B. По умолчанию False. |
| Параметры | enable_flash_attention: Включать ли Flash Attention. По умолчанию False.<br>Примечание: FlashAttention основан на https://arxiv.org/abs/2307.08691; использование кэша внутри цикла позволяет ускорить обработку и снизить расход пропускной способности. ### 2.4 Построение модели RKNN

<!-- source: EN PDF p14; unit 77 -->

| API | build |
| --- | --- |
| Описание | Собрать соответствующую модель RKNN на основе импортированной модели. |
| Параметры | do_quantization: Выполнять ли квантование модели. По умолчанию True. |
| Параметры | dataset: Входной набор данных для калибровки параметров квантования. Поддерживается текстовый файл с путями к изображениям (jpg или png) либо файлам npy для калибровки. | Параметры | auto_hybrid: Включать ли автоматическое смешанное квантование для коррекции точности или переполнения. По умолчанию False: коррекция не выполняется. | Возвращаемое значение | 0: Сборка выполнена успешно. |
| Возвращаемое значение | -1: Ошибка сборки. |

### 2.16 Регистрация пользовательского оператора

<!-- source: EN PDF p24; unit 151 -->

Интерфейс регистрирует пользовательский оператор.

<!-- source: EN PDF p24; unit 152 -->

| API | reg_custom_op |
| --- | --- |
| Описание | Зарегистрировать пользовательский оператор; поддерживается только для модели ONNX. |
| Параметры | custom_op: Класс пользовательского оператора для создания нового OP вне спецификации операторов ONNX. Рекомендуется начинать op_type нового OP с 'cst'; пользователь должен реализовать функции shape_infer и compute.<br>Примечание: класс custom_op используется только при преобразовании модели и генерации моделей RKNN с пользовательскими операторами. Для развёртывания на устройстве также следует обратиться к главе 5.5 'RKNN SDK User Guide'. |
| Возвращаемое значение | 0: Успешно. |
| Возвращаемое значение | -1: Ошибка. |

<!-- source: EN PDF p24; unit 153 -->

Пример кода:

<!-- source: EN PDF p24; unit 154 -->

```text
import numpy as np
from rknn.api.custom_op import get_node_attr
class cstSoftmax:
  op_type = 'cstSoftmax'
  def shape_infer(self, node, in_shapes, in_dtypes):
    out_shapes = in_shapes.copy()
    out_dtypes = in_dtypes.copy()
    return out_shapes, out_dtypes
  def compute(self, node, inputs):
    x = inputs[0]
    axis = get_node_attr(node, 'axis')
    x_max = np.max(x, axis=axis, keepdims=True)
    tmp = np.exp(x - x_max)
    s = np.sum(tmp, axis=axis, keepdims=True)
    outputs = [tmp / s]
    return outputs

ret = rknn.reg_custom_op(cstSoftmax)
```
