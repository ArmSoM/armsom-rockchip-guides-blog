## 8 Оценка точности, производительности и памяти API

<!-- source EN p23 unit 123 -->

### 8.1 Анализ точности квантования

<!-- source EN p23 unit 124 -->

Интерфейс выполняет инференс квантованной модели и формирует выходы каждого слоя для анализа точности квантования.

<!-- source EN p23 unit 125 -->

| API | accuracy_analysis |
| --- | --- |
| Описание | Выполнить инференс квантованной модели и создать снимок, то есть выгрузить данные тензоров каждого слоя. Для вычисления ошибки квантования выгружаются оба типа данных: fp32 и quant.<br>Примечания:<br>1. Интерфейс вызывается только после build или hybrid_quantization_step2.<br>2. Если target равно None, а исходная модель уже квантована (модель QAT), вызов завершится ошибкой.<br>3. Метод квантования соответствует настройке config. |
| Параметр | inputs: Список путей к изображениям (jpg/png/bmp/npy). |
| Параметр | output_dir: Каталог вывода всех данных снимка. По умолчанию './snapshot'.<br>Если target не задан, в output_dir создаются:<br>- Каталог simulator: результаты каждого слоя симулятора при полном выполнении квантованной модели (выход преобразован в float32).<br>- Каталог golden: результаты каждого слоя симулятора при полном выполнении модели с плавающей точкой.<br>- error_analysis.txt: косинусное расстояние (entire_error и single_error) между результатом каждого слоя квантованной модели в симуляторе и моделью с плавающей точкой в симуляторе при полном вычислении квантованной модели. Различие entire_error/single_error заключается в том, поступает ли вход каждого слоя из квантованной модели или модели с плавающей точкой. Подробнее см. error_analysis.txt.<br>Если target задан, в output_dir дополнительно создаются:<br>- Каталог runtime: результаты каждого слоя при полном выполнении квантованной модели на NPU (выход преобразован в float32).<br>- error_analysis.txt: дополнительно записывается косинусное расстояние (entire_error) между результатами каждого слоя симулятора и NPU при полном вычислении квантованной модели. Подробнее см. error_analysis.txt. |
| Параметр | target: Целевая аппаратная платформа. Поддерживаются 'rv1103', 'rv1103b', 'rv1106', 'rv1106b', 'rv1126b', 'rk3562', 'rk3566', 'rk3568', 'rk3576' и 'rk3588'. По умолчанию "None".<br>Если target задан, получаются выходы каждого слоя NPU и анализируется их точность. |
| Параметр | device_id: Идентификатор устройства. При подключении нескольких устройств к ПК его необходимо указать; значение получают через list_devices. По умолчанию "None ". |
| Возвращаемое значение | 0: Успешно. |
| Возвращаемое значение | -1: Ошибка. |

<!-- source EN p23 unit 126 -->

Пример кода:

<!-- source EN p24 unit 127 -->

```python
# Accuracy analysis
ret = rknn.accuracy_analysis(inputs=['./dog_224x224.jpg'])
```

### 8.2 Оценка производительности модели

<!-- source EN p24 unit 129 -->

| API | eval_perf |
| --- | --- |
| Описание | Оценить производительность модели.<br>Модель должна выполняться на RV1103 / RV1103B / RV1106 / RV1106B / RV1126B / RK3562 / RK3566 / RK3568 / RK3576 / RK3588, подключённом к ПК. Если при init_runtime параметр perf_debug равен False, аппаратная информация о производительности содержит только полное время выполнения модели. При perf_debug = True подробно измеряется и время каждого слоя. |
| Параметр | is_print: Выводить ли информацию о производительности. По умолчанию True. |
| Параметр | fix_freq: Фиксировать ли аппаратную частоту. По умолчанию True. |
| Возвращаемое значение | perf_result: Информация о производительности (строки). |

<!-- source EN p24 unit 130 -->

Пример кода:

<!-- source EN p24 unit 131 -->

```python
# Evaluate model performance
perf_detail = rknn.eval_perf()
```

### 8.3 Оценка использования памяти

<!-- source EN p24 unit 133 -->

| API | eval_memory |
| --- | --- |
| Описание | Получить потребление памяти при выполнении модели на аппаратной платформе.<br>Модель должна выполняться на подключённом к ПК RV1103 / RV1103B / RV1106 / RV1106B / RV1126B / RK3562 / RK3566 / RK3568 / RK3576 / RK3588. |
| Параметр | is_print: Выводить ли результаты оценки памяти в стандартном формате. По умолчанию True. |
| Возвращаемое значение | memory_detail: Подробные сведения об использовании памяти в формате словаря.<br>Пример данных:<br>{<br>'weight_memory': 3698688,<br>'internal_memory': 1756160,<br>'other_memory': 484352,<br>'total_memory': 5939200,<br>}<br>- 'weight_memory' — объём памяти весов модели.<br>- 'internal_memory' — память внутренних тензоров модели.<br>- 'other_memory' — память других тензоров модели.<br>- 'total_memory' — общий объём памяти модели, сумма памяти весов, внутренних тензоров и прочей памяти. |

<!-- source EN p24 unit 134 -->

Пример кода:

<!-- source EN p25 unit 135 -->

```python
# eval memory usage
memory_detail = rknn.eval_memory()
```

## Источник и редакционные примечания

Технические главы разделены по назначению. Код, идентификаторы и параметры сохранены. Китайская версия следует китайскому оригиналу; английская, русская и немецкая — английскому. В главы без иллюстраций вымышленные изображения не добавлены.

Примечания: журналы с SDK 1.5.2 сохранены как исторические примеры, а не измерения V2.5.0. Ячейка Python для Ubuntu20.04 различается: китайский текст 3.8/3.9, английский 3.8/3.8; аналогично для Debian11; в разделе ARM64 Debian всё ещё помечен x64. Значения сохранены; проверяйте фактический установочный пакет. V2.5.0 добавляет главу C++ codegen и уточняет квантование и стратегии памяти; параметры старой версии не подменяют новый источник.
