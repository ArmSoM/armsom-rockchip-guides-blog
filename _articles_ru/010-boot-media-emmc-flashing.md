# Безопасная работа с boot media и прошивкой eMMC на ArmSoM Rockchip

Создайте безопасный процесс прошивки с сохранением доказательств и без превращения recovery-инструмента в универсальное решение.

![Схема рабочего процесса: Безопасная работа с boot media и прошивкой eMMC на ArmSoM Rockchip](/assets/010-boot-media-emmc-flashing-flow.svg)

## Что помогает решить эта статья

Происхождение образа, ревизия платы, целевой boot device и план отката должны быть частью производственной записи. Это инженерный workflow, а не замена схеме, release notes или требованиям безопасности для конкретного изделия и ревизии ArmSoM.

## Контекст платформы

ArmSoM предоставляет ОС и документацию для конкретных плат. Разметку носителя и recovery-процедуру берите только из руководства нужного изделия. На практике фиксируйте вместе плату, версию BSP/образа, ревизию периферии, питание и воспроизводимые команды. Так полевые проблемы остаются диагностируемыми, а рабочая лабораторная конфигурация не превращается в скрытую зависимость.

## Воспроизводимая отправная точка

Сначала проверьте руководство для конкретной платы, версию образа и подключение интерфейса, затем выполните минимальную проверку. Сохраняйте вывод команд, версию ядра и образа, ревизию платы и идентификаторы периферии.

```bash
sha256sum image.img
lsblk
# Confirm the target device manually before using any flashing tool
```

![Схема цикла проверки: Безопасная работа с boot media и прошивкой eMMC на ArmSoM Rockchip](/assets/010-boot-media-emmc-flashing-validation.svg)

## Контрольный список

- [ ] Подтвердите плату ArmSoM, ревизию, SKU памяти/накопителя и питание.
- [ ] Сохраните `uname -a`, версию образа и полный serial boot log.
- [ ] До оптимизации убедитесь, что нужный hardware node или connector существует.
- [ ] Меняйте только один параметр за раз и сохраняйте evidence до и после.
- [ ] Для любого результата укажите нагрузку, среду, версии ПО и методику.

## Устранение неполадок

**Симптом: ожидаемое устройство или поведение отсутствует.** Сверьте running image и Device Tree с документацией изделия, затем проверьте питание, направление кабеля, посадку разъема и boot logs.

**Симптом: команда существует, но результат неверный.** Не принимайте пример команды за проверенную конфигурацию изделия. Проверьте pinmux, драйверы, device nodes, права и версии software stack для конкретной платы.

**Симптом: конфигурация пропадает после перезагрузки.** Определите, где должно находиться изменение: в образе, boot configuration, Device Tree, service definition или временной команде. Сохраните serial log и минимальный reproduction.
