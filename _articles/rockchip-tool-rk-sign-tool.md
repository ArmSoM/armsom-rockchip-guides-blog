## sign_tool V1.0: signing, verification and external signing

This section converts the complete bundled command-line signing manual. Examples use `sign_tool`; they do not imply identical options in every `rk_sign_tool` version. Signing is distinct from OTP/eFuse programming. Flag `0x20` explicitly enables miniloader OTP writing and must be reviewed against the matching Secure Boot design.

| SoC | Digest | Signature | Padding |
|---|---|---|---|
| 3229, 3228h, 3368, 3228, 3288, 3399, 3328 | SHA256 | RSA2048 | NOPADD |
| 3588, 3566, 3568, 3308, 3326, px30, 1808, 3228P, 1109, 1126, 2206 | SHA256 | RSA2048 | PSSPADD |

### 1. Preparation

Generate an RSA2048 key pair, explicitly with `--bits=2048` or with the source default. Select the chip, then load the private/public keys. These choices are saved and need not be repeated if unchanged. `1126` and filenames below are examples.

```text
sign_tool kk --bits=2048
sign_tool kk
sign_tool cc --chip=1126
sign_tool.exe lk --key private_key.pem --pubkey public_key.pem
```

Optional signing flags and the intermediate-data directory follow. The directory can also supply input for external signing. The two `kk` commands are alternatives, not an instruction to generate keys twice.

```text
sign_tool ss --flag=0x20
sign_tool ss --out .\data_out
```

### 2. Sign and verify five object types

A complete update image is unpacked, its loader/uboot/boot/trust components signed, and repacked, which takes longer. For A/B schemes the tool must not sign boot: set `exclude_boot_sign=true` in `setting.ini`. Loader signing inserts security structures during unpack/repack. IDBlock is generated by mkimage and contains boot structures, DDR initialization and Boot code. DDR-test configurations and uboot/trust/boot images have separate commands.

```text
sign_tool sf --firmware update.img
sign_tool vf --firmware update.img

sign_tool sl --loader miniloader.bin
sign_tool vl --loader miniloader.bin

sign_tool sb --idb 1126_idblock.bin
sign_tool vb --idb 1126_idblock.bin

sign_tool sd --cfg 1126_ddr_test.cfg
sign_tool vd --cfg 1126_ddr_test.cfg

sign_tool si --img uboot.img
sign_tool vi --img uboot.img
```

### 3.1 Extract data to sign

Extraction can use only the public key. Set extract and the output directory, then run any signing operation from section 2; the example extracts from update.img.

```text
sign_tool ss --extract
sign_tool ss --out wait_sign_dir
sign_tool sf --firmware update.img
```

### 3.2 Sign externally

Sign every file with the private key and put the results back in `wait_sign_dir` under the original filenames. The PSS example is restored to one command line with unchanged arguments. For NOPADD, create a zero-filled 256-byte buffer, copy the SHA256 digest into its last 32 bytes, then run the second command. Match the algorithm to the chip table.

```text
openssl pkeyutl -sign -in to_sign.bin -inkey privatekey.pem -out signed.bin -pkeyopt digest:sha256 -pkeyopt rsa_padding_mode:pss -pkeyopt rsa_pss_saltlen:-1

openssl rsautl -sign -in to_sign.bin -inkey privatekey.pem -raw -out signed.bin
```

### 3.3 Inject signatures

```text
sign_tool ss --inject
sign_tool sf --firmware update.img
```

The tool reads signatures from the previously configured directory and injects them into the corresponding locations. Verify afterward with the matching `v*` command. No signing, OTP programming or device flashing was performed for this article.
