## 原文疑点（未静默改写）

1. §1 称每个 HDCP2.3 控制器均有 3 Port，但文本/原图仅给 HDCP0 两个输出 DPTX0、DPTX1，HDCP1 三个输出；不能据此推导不存在的第3个 DPTX 端口。
2. §2.5 RX+TX 选择 HDMI 类型却写输出 `hdpc2_dp.fw`；DPTX 类型却写 `hdpc2_hdmi.fw`。后文对应流程又出现不同路径。保留全部原始信息，实际文件以打包工具输出核对。
3. `hdpc2_*` 与 `hdcp2_*` 在原文混用；不将拼写统一当作已证实修复。
4. §4.2.2 与 §4.3.2 文字要求拷贝 `hdcp_transmitter.bin`，紧随的命令却是 `hdcp_receivers.bin`。中英文均存在，命令原样保留，执行前必须核对实际目标。
5. 文中小标题 `hdcp2_rx_tx` 与实际二进制 `hdcp2_tx_rx` 不同；原始信息保留。
6. §2.6 前面为 PKf/DUK，后面写 Kf/DUK；未猜测改名。
7. §5 状态英文为 `Authentication success`，中文例子有 `Authenticated success`；`No dectypted` 拼写也来自原文。保留各自源字符串，不承诺所有 SDK 输出一致。
8. §5.2 明确当前驱动并未实际支持 HDCP Content Type 选择，不能将 Type1 的解释写成已验证功能。

密钥/固件烧写会修改设备。十六进制值为文档示例，不含实际私有密钥，也不能作为生产密钥。没有进行烧写、OTP、认证、播放或安全测试；未承诺 ArmSoM 实测结果。
