## 原文疑点及待核对事项

1. 封面日期 2024-03-28，修订表 V1.2.0 写 2024-03-29；以版本号追踪，不推断日期。
2. 产品版本表没有 RK3576，但正文和功能表包含 RK3576；内核版本为汇总列，不能解释为所有 SoC/内核组合均支持。
3. 多处引用仍为 3.x，现有文章主体为 2.x。译文在可确定时同时给出现行章节与源引用；§2.1.9.2 指向 §2.1.5.2 的 PLL 计算引用实际指向 HDCP，不能猜测缺失计算说明。
4. 第 16、18、20 页 PHY 参数均为 `340000000`，解释却说适用于 TMDS clock 低于 `165MHz`；这是原文矛盾，不改常量。
5. 第 29 页查询副显表写 `vendor.hwc.device.main`，与主显相同；原样保留，待目标 HWC 核实。
6. §2.3.9.1 Android 7/8 使用 persist.sys.brightness.main，文字却要求更新 vendor.display.timeline；示例又可能使用 sys.display.timeline。按原稿保留，不静默统一。
7. overscan 新属性表称“设置 HDMI0 颜色”，上下文实际为 overscan；英俄明确说明原文措辞，不改变属性名。
8. 8bit/10bit/12bit/16bit 状态枚举不等于每个 SoC 都支持这些位深；§2.1.9.3 的 8/10bit 说明属于源实现范围。
9. `Colorimery`、`ITU.BIT709`、`sloop boost`、`def_mode`/`def_modes` 等原文拼写及命名混用保持可追溯。不得未经核实改写硬件寄存器或 API 名称。
10. 信号强度、共享 PHY、强制输出和 HDCP key 操作必须在合法授权、可恢复的目标板环境核对；本文未执行任何命令或烧录密钥。原文 50kHz I2C 与 4K25Hz UI 数据不是 ArmSoM 实测。
