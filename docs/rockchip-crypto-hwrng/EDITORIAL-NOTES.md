## 已发现的源文问题与保留规则

1. **删除线具有技术意义**：英文 PDF 第 10 页 §2.1.2 用删除线表示驱动尚未实现的算法模式。已查看该页渲染图；不可将纯文本提取后失去删除线的列表作为“全部已支持”的列表发布。AES/SM4 的 XTS、CTS、CCM、CBC-MAC/CMAC，以及 HASH 列表中的 SHA512_224/SHA512_384 有删除线。需与中文对应页逐项对照。
2. **算法名称内部矛盾**：英文 §1.2 列出 SHA512-224/SHA512-256；§2.1.2 删除线列表却写 SHA512_224/SHA512_384。枚举又是 `RK_ALGO_SHA512_224` 和 `RK_ALGO_SHA512_256`。保留原始拼写及上下文，不能把 `_384` 静默改成 `_256`。
3. **标识符拼写**：`RK_CIPIHER_MODE` 是源代码枚举名，尽管看似拼写错误，不按自然语言拼写修正。
4. **标题与代码枚举名不同**：§3.2.5.3 标题为 `RK_OEM_HR_OTP_KEYID`，代码声明为 `enum RK_OEM_OTP_KEYID`。记录差异，不修改 API 常量。
5. **AEAD tag 方向**：英文 §3.2.6.25/26 将 `tag` 说明为“input for encryption, output for decryption”，疑似输入输出方向倒置；保留源文信息，并在最终正文附近提示需对照对应 SDK 实现确认。
6. **虚拟地址接口的参数说明**：英文 §3.2.6.21 使用 `src`/`dst`，注意事项却提到 `in_fd`/`out_fd`。§3.2.6.24 声明 `aad_virt`，参数描述写 `in`。不得把这些差异当作已验证接口行为。
7. **RSA 填充枚举注释**：§3.2.5.7 中 PSS_SHA384、PSS_SHA512 的注释分别写 SHA1、SHA256，疑似复制错误。代码及注释保留，另行提示。
8. **RSA 测试公式**：英文第 50 页同时使用 `d` 表示参与运算的数据和私钥指数，表达不清；不猜测替换变量。
9. **缺少函数原型**：英文 §3.2.6.22 `rk_ae_init` 标题后直接进入功能说明。已渲染检查英文第 41 页，原文确实没有函数声明；中文也无原型，不根据其它接口编造声明。
10. **空章节**：已渲染核对英文最后一页（第 52 页）及中文最后一页（第 49 页），§6 References、§7 Appendix、§7.1 Professional Term 确实只有标题，没有后续正文。三语保留标题并说明为空章节。
11. **同版本文本差异**：中文 §1.1 明确 TDES 支持 EEE/EDE，§1.2 明确只支持 EDE；英文对应表未完整写出这些限制。最终稿需显式注明中文补充来源，不能误称英文原稿已有该信息。

## 补充原文差异与疑点

- §3.2.6.25/26 的 tag 方向并非仅疑似问题：中文明确为加密 out、解密 in，英文相反。三语正文附近已显式标明冲突；没有静默混用源版本，最终行为须按 SDK 实现核验。
- §3.2.4.3 的 `key`：中文写 keyladder 操作时无效，英文写 otp key；各自保留，不能视为两个词在所有 SDK 中同义。
- §3.2.3 的 CMA 起始地址 `0x10000000`：中文是“尽量不要修改”，英文是“do not change”；保留措辞差异，地址值均不变。
- §4.2.2 中文写 V3 最高 350M，英文写 V3/V4。正文依各自来源保留，不能据此保证某个板卡的最高频率。
- §3.2.6.24 中文注意事项中出现 `rk_ae_set_virt` 和 `add`，与小节/API 的 `rk_ae_set_aad_virt`/AAD 不一致；保留为源文疑点。
- §2.1.2 的 SM4 模式列表重复 OFB；英文硬件差异表 RK1808 的 HASH 单元格写 `SHA-1SHA-224`，中文有 `/`。源文保留，不将其解释成新的算法名。
- §5.1 推荐 CTR 是原文陈述，不构成对任意协议的安全建议；应结合认证、IV/nonce 使用及完整威胁模型。文章未新增“所有算法均安全”的结论。
- 采用平台参考适用说明：未确认具体 ArmSoM 板卡的 BSP/TEE/OTP 适配，不填写未经验证的产品支持列表。源文的 kernel 4.19/5.10/6.1 提交依赖完整保留，代码中的提交作者及 Signed-off-by 作为技术溯源保留。
