## 原稿疑点（未猜测修正）

1. 部分交叉引用仍为旧章节号，例如 3.1.7、6.1、6.2、9.1、16.1；正文保留可追溯信息，以本系列实际章节及对应 API 手册定位。
2. 动态 Shape 容量示例 EN p108 写作 `1224+140=264`、`1112+180=192`。目视原 PDF 确实如此，疑似乘号排版缺失；没有默改为新的算式。执行前核对真实 shape。
3. Matmul 的 TP_NORM 支持表述存在相互矛盾；以具体 SoC 的 V2.5.0 头文件、支持表和实际模型验证为准。英文单元 1289 的 `RK1126B` 拼写按原文保留，并标注原稿写法。
4. `init()`、`rknn.val_perf()` 与后文 `load_rknn()`/`init_runtime()`、`rknn.eval_perf()` 描述不一致；正文不把疑似拼写错误包装为已验证 API。
5. 英文代码 `voi norm_layout_to_native_layout` 疑似原稿拼写；动态 Shape 示例定义 `dynamic_input` 却传 `dynamic_shapes`；QAT 示例中的 `torch.nn.Conv`、`train_loop` 参数和循环位置也需核对。源码技术内容保留，代码记录中列出。
6. 中文量化示例有正确 Python 缩进，英文 PDF 同例缩进缺失；英文按中文对应示例恢复缩进，参数不变。EN557 的 Python 缩进同样按 CN531 校正。
7. FAQ 保留旧版历史回答，例如“无 ARM Linux Toolkit2”与前文 ARM64 安装说明不一致；不能把历史答复视为当前所有平台支持结论。
8. FAQ 一处写 3 种量化算法，前文列出含 GDQ 的 4 种；校正图片数量有 20–100、20–200 等不同场景表述。保留各段条件，不静默统一。
9. FAQ 的 fp16 上限写 `65536`，前文范围为 `-65504～65504`；两处原始信息保留，不能将前者作为执行边界。表格中的 `RKNN_TENSOR_UIN8` 疑似 `UINT8` 拼写也保留源信息。
10. Runtime 基础段称当前不提供异步接口，其他 API/flag 的实际能力需按 SDK 核对，不据此推断所有版本都不支持异步。
11. 样例重复权重分配代码、图中 `rknn_create_mem_from_phy` 与正文 `rknn_create_mem_from_phys` 等均需按真实头文件核对；未因“看起来重复/拼错”而删除原始信息。
