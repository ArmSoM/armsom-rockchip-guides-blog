## 原文疑点，不擅自改值

1. **适用范围冲突**：p.2 表为 RK3566/RK3568，内核栏为空；p.9 正文为 ISP30/RK3588；p.77 写 RK1109。保留原表并在前言明确，不能据此确定具体板卡/BSP/内核支持。
2. **技术版本**：原记录 V2.0.0 转 JSON，AIQ V2.0x60.0/IQ Tool V2.0.2；V2.0.1 ISP21/RK356X；V3.0.0 ISP30/RK3588；V3.0.1 删除 CCM/3DLUT 手动 JSON 配置；V3.0.2 升级 AWB 仿真至 IQ Tool V2.1.0。封面与修订日期次序不一致，不据此制造文章 lastmod；本稿文章日期为整理日期 2026-10-19。
3. **p.12** 示例同时出现 `control.bypass` 和 `control.wbBypass`，原样保留。`frameChoose` 表只描述两帧 HDR 的 0/1，而 p.51 日志说明描述三帧 0/1/2；按各自上下文保留。
4. **p.14** `lscBypassEnable` 名称含 bypass，但说明为 0 不启用 LSC、1 启用。未因字段名逆转语义。
5. **p.18 / p.30 / p.56** 存在功能未实现/当前 JSON 工具不支持/在线 RAW 暂不支持的说明，后面仍有操作示例；均保留，实际能力需按工具版本核实。
6. **p.21–22** 亮度阈值范围写 `[0-2555000]`，其他章节多为 0-255000；保留多出的位数，不擅自改成常见值。`ratioSet_len` 说明写高可信白点数量，非明确曲线长度；如实保留。
7. **p.23–27** 保留 `wight`、`totalPixe`、`staWeigthSet`、`staWeigth` 等原文标识拼法。p.27 `wpNumPercTh*totalPixel` 和 `wight * height` 的乘号由视觉恢复，未改参数。区间策略的 WPType1/WPType3 与个别表格叙述存在交叉，未统一猜改。
8. **p.29** `wbGainClip.eanble` 拼写保留；`cri_bound_up` 对应下边界且使用负号，`cri_bound_low` 对应上边界。室外 minimum CCT 判断写 `cct0 >outdoor_cct_min`，未改比较方向。
9. **p.30** 表中末行字段 `lutAll.ct_in_range_len/lutAll.cri_in_range_len/lutAll.cri_out_len/lutAll.cri_out` 有重复/缺少后缀的可能，原样保留。ct 从冷到暖及范围 0-255000 为原文说法，未替换为通常色温惯例。
10. **p.37** 框选稳定说明混用 `xyRegionSize`、`xyTypeListSize`、`LvVarTh`、`varianceLumaTh`，保留每处原名。末段为含自然语言条件的伪代码，并非可直接编译的 C。
