## 原文疑点（未擅自改为推测值）

1. PDF p6 的 IPv6 字串为 `FF0x:0:0:0:0:0:0:0:0:181` 与 `FF02:0:0:0:0:0:0:0:0:6B`，分组数和写法疑有问题；三语保留原字串并提示，工程配置应对照对应标准及驱动实现。没有静默缩写成另一地址。
2. PDF p9 工具名写 `phy2sys`，同段及后文命令为 `phc2sys`；前者按原文保留，不能据此认定存在同名可用工具。
3. PDF p11 文字写 CST 比 UTC “behind” 八个时区，但后面的 19:51:52 CST / 11:51:52 UTC 示例表现相反。三语显式说明矛盾，保留全部原始输出，不把错误方向作为新的事实。
4. PDF p11 的 gPTP 全称写 `general precise time protocol`。原措辞保留为来源表述，未替换成外部推测术语。
5. PDF p12 第一行 gPTP 日志将配置参数串放在 `selected /dev/ptp0 as PTP clock` 之后；首个 RMS/max 为极大整数。原样保留，不把异常首样本描述为稳定精度。
6. PDF p15 的两个后台 ptp4l 命令主从均用 eth0，而第 2.3 节主端用 end0；这是不同原文示例，执行前须核对实际网络接口和 PTP clock。文档没有提供 gPTP.cfg 的内容，未凭空补文件。
7. 源表 Kernel Version 为 ALL，且 PPS 支持排除 RK3568/RV1126；不能把这种平台范围扩展为所有 ArmSoM 产品的板级能力。
